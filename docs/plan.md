# 폴드8 최적화 사진편집 앱 기획서

Oct 16, 2026 · @9dongb

## 개요

갤럭시 Z 폴드8의 커버 화면(10:16)과 메인 화면(4:3)에 각각 맞춘 레이아웃을 가진, 레이어 기반 사진 편집 앱을 만든다. 다른 폰과 태블릿은 화면 폭에 따라 같은 레이아웃 규칙을 적용해 대응한다.

- **한 줄 소개:** 접으면 빠른 보정, 펼치면 포토샵급 편집
- **목표:** 포토샵의 핵심 기능을 단계적으로 구현하되, 폴드 화면 전환이 가장 자연스러운 편집 앱
- **주 대상 사용자:** 폰으로 사진을 자주 보정하고, 레이어·마스크 같은 고급 기능도 쓰고 싶은 사용자
- **대상 기기:** 갤럭시 Z 폴드8 우선, 이후 일반 안드로이드 폰·폴더블·태블릿 (폴드8 Ultra 전용 최적화는 현재 계획 없음)

**앱 이름:** Stratum (브랜드: Kiln) · **디자인 방향:** 전문가 툴 — 도구 막대와 패널 중심, 캔버스를 가장 넓게 쓰는 화면

## 대상 화면 사양

폴드8은 커버가 일반 폰에 가까운 세로형(10:16), 메인이 소형 태블릿에 가까운 정사각형에 가까운 비율(4:3)이다. 안드로이드 화면 크기 분류로 보면 커버는 '좁은 화면(Compact)', 메인 세로는 '중간(Medium)', 메인 가로는 '넓은 화면(Expanded)'에 해당한다.

| --- | --- | --- | --- | --- | --- | --- |
| 커버 화면 | 5.5인치 | 1248 × 1972 | 10:16 | 약 428ppi | 약 475dp | Compact (600dp 미만) |
| 메인 화면 (세로로 들기) | 7.6인치 | 1848 × 2448 | 3:4 | 약 403ppi | 약 700dp | Medium (600\~840dp) |
| 메인 화면 (가로로 들기) | 7.6인치 | 2448 × 1848 | 4:3 | 약 403ppi | 약 930dp | Expanded (840dp 이상) |

**다른 기기 대응 원칙**

- 기기 이름이 아니라 **화면 폭(dp)** 으로 레이아웃을 고른다. 그래야 폴드8 Ultra(커버 6.5인치, 메인 8.0인치), 일반 폰, 태블릿에서도 자동으로 맞는 화면이 나온다.
- Compact = 커버 화면 레이아웃, Medium = 메인 세로 레이아웃, Expanded = 메인 가로·태블릿 레이아웃.
- 메인 화면 가운데 접히는 부분(힌지)은 피하지 않는다. 펼친 화면은 평평한 한 화면으로 쓴다(2026-10-21 사용자 요청으로 바꿈, 전에는 버튼·슬라이더를 두지 않았다).

## 화면별 UI 전략

커버 화면은 한 손으로 쓰는 '빠른 보정' 화면, 메인 화면은 패널을 펼쳐 놓고 쓰는 '전체 편집' 화면으로 나눈다. 두 화면은 같은 편집 데이터를 공유하고, 접거나 펼쳐도 작업이 끊기지 않아야 한다.

| 화면 | 레이아웃 | 주요 용도 |
| --- | --- | --- |
| 커버 (10:16) | 위: 캔버스 / 아래: 한 줄 막대(고른 도구의 칩, 누르면 같은 줄이 슬라이더) + 도구 탭 1줄, 늘 같은 높이라 사진을 가리지 않는다. 조정·레이어는 상단 바 버튼(조정은 막대, 레이어는 막대 위 시트)(2026-10-21 커버 화면 개편) | 자르기, 밝기·색감 보정, 필터, 간단한 제거, 내보내기 |
| 메인 세로 (3:4) | 왼쪽: 도구 막대(고른 도구의 옵션은 그 오른쪽 좁은 띠) / 가운데: 캔버스 / 레이어·조정은 상단 바 버튼으로 켜고 끄는 떠 있는 패널(오른쪽 위, 끄기 전까지 열려 있음) | 레이어 편집, 선택·마스크, 브러시 작업 |
| 메인 가로 (4:3) | 메인 세로와 같다(2026-10-19 사용자 요청으로 고정 패널을 없앰) | 포토샵과 가장 비슷한 전체 편집 화면 |
| 테이블탑 (반쯤 접어 세움) | 위 절반: 캔버스 / 아래 절반: 도구·슬라이더 | 거치해 두고 세밀하게 보정 |

**화면 전환 규칙**

- 접기·펼치기 시 현재 이미지, 레이어, 선택 영역, 실행 취소 기록을 모두 유지한다.
- 커버에서 시작한 작업을 펼치면 같은 도구가 선택된 채로 메인 레이아웃으로 넘어간다.
- 커버 화면에서는 레이어 패널을 숨기고, 필요할 때만 아래에서 올라오는 시트로 연다.
- 캔버스 조작(두 손가락 확대·이동·회전)은 모든 화면에서 동일하게 동작한다.

## 화면 흐름

Stratum은 **홈 → 편집 → 내보내기** 세 단계가 중심이고, 모든 작업은 편집 화면 안에서 패널과 시트로 처리한다. 편집 내용은 프로젝트로 자동 저장되어, 앱을 닫았다 열어도 이어서 작업할 수 있다.

&#91;embedded content: Stratum 화면 흐름\]

편집 화면에서 뒤로 가면 홈으로 돌아가고, 그 사이 작업은 프로젝트로 자동 저장된다(도구를 골라 둔 채면 먼저 그 도구를 닫는다, 2026-10-18 사용자 요청). 내보내기는 원본 프로젝트를 바꾸지 않고 복사본만 만든다.

**화면 목록**

| 화면 | 들어오는 경로 | 주요 요소 | 커버 화면 | 메인 화면 |
| --- | --- | --- | --- | --- |
| 홈 | 앱 실행, 편집 화면에서 뒤로 | 프로젝트 갤러리(그림 비율대로의 작은 그림·이름·크기), 위 줄의 선택·사진 열기·새 캔버스(+)(2026-10-19 사용자 요청, 프로크리에이트 갤러리 방식. 설정은 2026-10-21부터 편집 화면 상단 바) | 썸네일 2열 | 썸네일 4열 |
| 사진 선택 | 홈의 '사진 열기' | 안드로이드 기본 사진 선택기(갤러리 권한 불필요) | 시스템 화면 | 시스템 화면 |
| 새 캔버스 | 홈의 '+'(새 캔버스) | 이름, 기본 크기 프리셋(정사각형 1:1, 세로 4:5, 스토리·쇼츠 9:16, 가로 16:9, 사진 3:2·4:3, 폴드8 커버·메인 배경화면), 직접 입력, 방향, 배경색 | 아래에서 올라오는 시트 | 두 칸 창(왼쪽 프리셋 목록, 오른쪽 이름·크기·방향·배경, 2026-10-19 사용자 요청: 프로크리에이트·포토샵 참고) |

| 도구 옵션·조정 시트 | 편집 화면에서 도구 선택 | 슬라이더, 프리셋, 적용·취소 | 한 줄 막대(칩을 누르면 같은 줄이 슬라이더·고를 것, 곡선만 막대 위에 뜸) | 도구 옵션은 도구 막대 오른쪽 좁은 띠(도구 막대 폭, 고른 도구 옆에 칸만큼의 높이로 뜸, 칸을 누르면 옆에 슬라이더·목록 창), 조정은 떠 있는 패널(2026-10-19 사용자 요청) |
| 내보내기 | 편집 화면 상단 바의 내보내기(공유 아이콘, 2026-10-21 사용자 요청) | 형식(JPEG·PNG·WebP), 품질, 크기, 메타데이터 포함 여부 → 갤러리 저장 또는 공유 | 전체 화면 시트 | 오른쪽 패널 또는 대화상자 |
| 설정 | 편집 화면 상단 바 맨 오른쪽 설정 버튼(2026-10-21 사용자 요청, 뒤로 가면 편집 화면) | 미리보기 해상도(성능), 기본 내보내기 형식, 제스처, 앱 정보 | 목록 | 2단(분류 · 항목) |

**확정 사항**

- [x] **홈 화면:** 앱을 열면 항상 홈부터 보여준다

- [x] **프로젝트 보관 위치:** 앱 내부 저장, 갤러리에는 내보내기로만 저장

## 기능 우선순위 제안

포토샵 기능을 한 번에 넣으면 바이브 코딩으로는 완성이 어렵다. 레이어 엔진을 먼저 탄탄하게 만들고, 그 위에 기능을 쌓는 4단계로 나눈다.

1. **1단계 — 출시 가능한 최소 버전(MVP)**
   - 사진 열기, 프로젝트 자동 저장(레이어를 유지하는 자체 형식), 내보내기(JPEG·PNG·WebP, 품질·크기 선택)
   - 자르기(비율 고정), 회전, 뒤집기, 이미지 크기 변경
   - 기본 보정: 밝기, 대비, 노출, 채도, 색온도, 하이라이트·그림자, 곡선
   - 레이어: 추가·삭제·순서 변경, 불투명도, 혼합 모드 일부(표준·곱하기·스크린·오버레이)
   - 브러시, 지우개, 텍스트 기본
   - 실행 취소·다시 실행
   - 폴드8 커버·메인 화면별 레이아웃과 접기·펼치기 전환
2. **2단계 — 포토샵다운 편집**
   - 선택 도구: 사각형·원형, 올가미, 자동 선택(마술봉), 선택 영역 페더
   - 레이어 마스크, 클리핑 마스크, 비파괴 조정 레이어
   - 필터: 흐림, 선명, 노이즈, 비네팅, 그레인, LUT 색상 필터
   - 리터칭: 복제 도장, 스팟 복구
   - 그레이디언트, 도형, 레이어 스타일(그림자·획)
3. **3단계 — 고급·온디바이스 AI**
   - 피사체 선택·배경 제거(폰 안에서 실행되는 AI)
   - 개체 제거(인페인팅), 원근·뒤틀기 변형, 픽셀 유동화(재구성 도구로 문지른 부분만 원래대로 되돌리기 포함), 작업 내역 브러시(지정한 이전 상태로 칠한 부분만 복원)
   - PSD 가져오기·내보내기, RAW 열기, 액션(작업 녹화·반복)
4. **검토 필요 — 비용·규모가 큰 기능**
   - 생성형 채우기·확장·이미지 생성: 클라우드 AI API가 필요해 사용량만큼 비용 발생
   - CMYK·인쇄용 색상 관리, 32비트 HDR
   - 동영상·GIF 타임라인, 펜 도구 기반 벡터 편집

## 기술적 고려사항

이 앱은 이미지 처리 성능과 메모리가 핵심이라 **Kotlin + Jetpack Compose 네이티브 개발**로 확정했다. 이미지 엔진은 화면 코드와 분리된 모듈로 만들어, 나중에 다른 플랫폼으로 옮길 여지를 남긴다.

- **폴드 대응:** Jetpack WindowManager로 접힘 상태(펼침·반쯤 접힘)와 힌지 위치를 감지하고, 화면 크기 분류(Compact·Medium·Expanded)로 레이아웃을 바꾼다.
- **렌더링:** 필터와 보정의 실시간 미리보기는 GPU 셰이더(AGSL·OpenGL ES)로 처리한다. CPU로 처리하면 큰 사진에서 슬라이더가 끊긴다.
- **메모리:** 폴드8 50MP 사진(약 8160 × 6120)은 레이어 하나에 약 200MB(픽셀당 4바이트)다. 레이어 10개면 2GB이므로, 원본 픽셀을 앱의 기본 메모리(자바 힙) 밖에 타일 단위로 두고 편집을 원본에 바로 적용한다. 화면에는 축소본을 그리고, 원본 해상도 계산은 바뀐 타일만 한다. 레이어가 많아지면 쓰지 않는 타일을 저장 공간으로 내보낸다.
- **실행 취소:** 매번 전체 이미지를 복사하지 않고, 바뀐 영역(타일)과 편집 명령만 기록한다.
- **파일 형식:** 레이어를 보존하는 자체 프로젝트 형식을 먼저 만든다. PSD는 공개 규격이 복잡하고 안드로이드용 라이브러리가 적어 3단계로 미룬다.
- **AI 기능:** 피사체 선택·배경 제거는 폰 안에서 실행되는 모델(예: Google ML Kit 분할 기능)로 무료 구현이 가능하다. 생성형 채우기는 외부 AI API가 필요해 사용량 비용과 서버 관리가 생긴다.
- **입력:** 손가락 터치 기준으로 설계하고, 스타일러스를 지원하는 기기에서는 필압을 브러시 크기·불투명도에 반영한다.
- **바이브 코딩 난이도:** 1단계는 혼자서도 충분히 가능하다. 레이어·마스크·선택이 얽히는 2단계부터는 구조 설계가 중요하므로, 기능을 추가할 때마다 AI에게 기존 구조를 먼저 설명하게 하고 작은 단위로 커밋한다.

**구조: 엔진과 화면 분리**

- **engine 모듈:** 문서·레이어 데이터, 합성, 필터, 브러시 계산, 실행 취소 기록. 화면(Compose) 코드를 전혀 참조하지 않는다.
- **app 모듈:** Compose 화면, 폴드 레이아웃, 도구 패널. 엔진에는 '레이어 추가', '밝기 +10' 같은 명령만 보내고 결과 이미지를 받아 그린다.
- 편집 상태가 엔진에만 있으므로 커버↔메인 전환, 실행 취소, 나중의 iOS 이식이 모두 쉬워진다.

* **전용 작업 모드:** 픽셀 유동화·선택 및 마스크처럼 전용 도구가 필요한 기능은 별도 화면으로 이동하지 않고, 편집 화면 위를 전체 화면으로 덮는 작업 모드로 띄운다. 확인하면 실행 취소 한 단계로 기록되고, 취소하면 즉시 원래 상태로 돌아간다.

**개발 환경**

- Mac + Android Studio로 빌드하고, 폴드8 실기기를 무선 디버깅(같은 Wi-Fi)으로 연결해 접기·펼치기를 직접 테스트한다. 에뮬레이터의 폴더블 프로필은 보조로만 쓴다.
- AI 코딩 도구는 Claude Code 하나만 쓴다. 큰 기능을 마친 뒤에는 Claude Code가 스스로 규칙 위반 여부를 다시 검토하게 한다.
- 프로젝트 루트에 규칙 파일(CLAUDE.md)을 두어, Claude Code가 매번 같은 설계 원칙을 따르게 한다.
