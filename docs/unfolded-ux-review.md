# 펼친 화면 UI/UX 점검 (2026-10-22)

- 사용자: "펼친화면의 UI/UX를 점검하려 합니다. 앱 사용 일관성, 태블릿 앱 사용성 관점에서 적합성, 폴더블(폴드8, 아이폰 듀오 기준) 사용성 관점에서 적합성을 확인하고 싶습니다. 잘 맞는 부분과, 보완하거나 개선해야할 부분이 있다면 알려주세요."
- 방법
  - 에뮬레이터(Pixel_Fold)의 펼친 화면을 가로·세로로, 사진을 열어 둘러봤다. 도구 띠, 세로 슬라이더, 하위 도구 메뉴, 선택 작업 표시줄, 레이어·조정 패널, 자르기, 내보내기, 설정, 홈을 봤고, 커버를 가로로 돌린 화면도 봤다.
  - 안드로이드·애플·삼성의 큰 화면 가이드와 프로크리에이트·포토샵 iPad·라이트룸을 조사해 견줬다(조사는 하위 에이전트, 출처는 맨 아래).
- 지금은 보고만 했다. 무엇을 할지는 사용자가 고른다.

## 조사로 확인한 사실

공식 페이지에서 직접 확인했다.

- **아이폰 듀오(iPhone Duo):** 애플의 첫 폴더블 아이폰이다(2026-09-09 발표, 10-23 출시). 책처럼 펼친다.
  - 안쪽 7.6형(1878×2670), 바깥 5.4형(1398×2034)이고 iOS 27.1이다.
  - 애플 개발자 안내: 바깥 화면은 좁은 폭(compact), 안쪽 화면은 어느 방향이든 넓은 폭·넓은 높이(regular/regular)다. 평평하게 펼치면 접는 선 영역의 폭은 0이다. 반쯤 접으면 위는 보기, 아래는 조작에 쓴다.
- **갤럭시 Z 폴드8(사용자 기기):** 안쪽 7.6형 4:3(1848×2448), 바깥 5.5형 10:16(1248×1972)이다.
  - **S펜과 Flex 모드(반 접어 세우기)를 지원하지 않는다**(삼성 공식 FAQ). 폴드8 울트라는 Flex 모드가 있다.
  - 크기를 dp로 따지면(420dpi 어림): 안쪽 가로 약 933×704, 세로 약 704×933, 바깥 가로 약 751×475, 안쪽 가로를 반으로 나눈 창 약 460 폭이다.
- **안드로이드 '적응형 앱 품질'(옛 큰 화면 앱 품질) 2등급:**
  - 터치 영역 48dp 이상.
  - 단축키: 고르기, 잘라내기, 복사, 붙여넣기, 실행 취소, 다시 실행.
  - Esc는 끝내기(자르기에서 버리고 나가기 포함).
  - 오른쪽 클릭 메뉴, Ctrl+휠·트랙패드 집기 확대, 마우스를 올리면 바뀌는 표시.

## 1. 앱 사용 일관성

잘 맞는 점
- 커버와 펼친 화면이 같은 도구·아이콘·이름·값 표시를 쓴다(같은 칸 코드).
- 조정·레이어·실행 취소·내보내기·설정이 두 화면에서 같은 자리(상단 바)이고, 켬·끔 상태도 같다.
- 접고 펴도 문서·도구·패널·보기가 이어진다.
- 하위 도구 메뉴(꾹 누르기·다시 누르기·끌어 고르기)가 두 화면에서 같다.
- 색·모양·부품이 한 테마에서 나온다. 창은 가운데에 뜨고, 설정은 2단이다.

보완할 점
- (중) **펼친 화면에서는 지금 고른 하위 도구가 보이지 않는다.**
  - 리터칭을 골라도 도구 막대 아이콘은 늘 반창고라, 스팟 복구인지 복제 도장인지 알 수 없다. 커버는 막대 맨 앞 칩에 보인다.
  - 제안: 포토샵처럼 도구 막대 아이콘을 고른 하위 도구의 아이콘으로 바꾼다. 띠의 하위 도구 칸은 다시 넣지 않는다(2026-10-20 사용자 결정).
- (소) **도구 안내 알림이 도구를 바꿔도 몇 초 남는다.** 리터칭 안내가 선택 도구로 바꾼 뒤에도 보였다. 제안: 도구를 바꾸면 그 안내를 바로 지운다.
- (소) **같은 값을 바꾸는 방법이 화면마다 다르다.** 커버는 칩 → 가로 슬라이더, 펼친 화면은 칸 → 세로 슬라이더·끌기다.
  - 화면 크기에 맞춘 차이라 괜찮다.
  - 커버 칩에도 '누른 채 끌기'를 넣으면 손맛이 같아진다(이미 다음 후보다).

## 2. 태블릿 앱 사용성

잘 맞는 점
- 캔버스가 먼저다: 왼쪽 도구 막대 위에 띠·패널이 떠 있고, 캔버스를 줄이지 않는다. 프로크리에이트·포토샵 iPad와 같은 계열이다.
- 태블릿 손맛에 맞는 조작이 있다.
  - 띠를 끌어 옮기면 그 자리를 기억한다.
  - 값 칸을 끌어 값을 바꾸고, 슬라이더는 세로다.
  - 두 손가락 톡은 실행 취소, 세 손가락 톡은 다시 실행이다(프로크리에이트·포토샵 iPad와 같은 약속).
- 선택 도구의 작업 표시줄이 아래 가운데에 있다(포토샵 iPad와 같은 자리).
- 설정은 2단, 창은 가운데에 알맞은 폭이다(안드로이드 큰 화면 배치 권장과 같다).

보완할 점
- (상) **키보드·마우스 지원이 없다(2등급 기준).**
  - 키보드: 실행 취소·다시 실행·복사·붙여넣기 단축키, Esc로 자르기 취소, 도구 키(B·E 등), [ ]로 크기 조절.
  - 마우스: Ctrl+휠 확대, 오른쪽 클릭 메뉴, 마우스를 올리면 바뀌는 표시.
  - 갤럭시 탭·덱스(DeX)·키보드 커버를 쓰는 사람에게 필요하다.
- (상) **배치를 창 폭으로만 고른다.**
  - 커버를 가로로 돌리면(폴드8 약 751×475dp) 폭이 600dp를 넘어 펼친 화면 배치가 뜬다.
  - 에뮬레이터 커버(약 797×411dp)에서 도구 막대에 11개 중 7개만 보였다(나머지는 밀어야 보임). 새 캔버스 창은 입력 칸이 잘렸다.
  - 제안: 높이가 낮은 창(480dp 미만)에서는 도구 막대도 커버처럼 6개 + 더보기로 줄이고, 두 칸 창은 한 줄로 쌓는다.
  - 안드로이드 17부터는 큰 화면에서 방향 고정이 무시되므로 꼭 맞춰야 한다.
- (중) **끌어 놓기(드래그 앤 드롭)가 없다.**
  - 창을 나눈 채 갤러리에서 사진을 끌어 와 열거나 새 레이어로 넣고, 결과를 끌어 다른 앱에 보내는 기능이다.
  - 폴드8도 창 나누기와 끌어 놓기를 지원한다.
- (중) **세로 화면에서 공간을 못 쓴다.**
  - 가로로 긴 사진을 펼친 화면 세로로 열면 사진 아래가 크게 빈다. 그런데 레이어·조정 패널은 사진 위 오른쪽 위에 겹쳐 뜬다.
  - 제안: 세로(중간 폭)에서는 패널을 아래 빈 곳에 붙인다. 안드로이드 '보조 창(supporting pane)' 배치가 중간 폭에서는 아래 시트나 50:50을 권한다.
- (중) **자주 누르는 버튼이 손에서 멀다.**
  - 실행 취소·다시 실행·조정·레이어가 모두 오른쪽 맨 위 얇은 바(높이 약 28dp)에 있다. 두 손으로 잡으면 멀고, 48dp 기준보다 작다(전에 정한 예외).
  - 라이트룸 iPad도 실행 취소가 위에 있어 사용자 불만이 있다.
  - 제안: 프로크리에이트처럼 도구 막대 아래쪽에 실행 취소·다시 실행을 두거나, 왼손·오른손 설정(도구 막대 좌우 바꾸기)을 둔다.
- (중, 태블릿용) **S펜 지원이 없다.**
  - 기대하는 기능: 필압으로 크기·불투명도 조절, 손바닥 무시, 펜 끝 지우개, '손가락은 화면 이동만' 설정, 펜을 올리면 브러시 원 미리 보기.
  - 폴드8에는 S펜이 없지만 갤럭시 탭에서는 기본으로 기대한다.
- (소) **도구 막대 아이콘에 이름이 없다.** 마우스나 펜을 올렸을 때 이름(툴팁)을 띄우면 처음 쓰는 사람에게 좋다.

## 3. 폴더블 사용성(폴드8·아이폰 듀오)

잘 맞는 점
- 접기·펼치기에 작업이 이어지고, 기기 이름이 아니라 화면 폭으로 배치를 고른다. 안드로이드·애플·삼성이 모두 가장 먼저 꼽는 원칙이다.
- 평평하게 펼쳤을 때 접히는 선을 무시하고 한 화면으로 쓰는 것도 세 곳 가이드와 같다.
- 잡는 방식에 맞다: 커버는 한 손(아래 막대), 펼친 화면은 두 손(왼쪽 도구 막대)이다.
- 아이폰 듀오도 바깥은 좁은 폭, 안쪽은 넓은 폭이라 지금 배치 규칙(커버 배치 / 펼친 화면 배치)이 그대로 들어맞는다.

보완할 점
- (상) **창 나누기·팝업 창에서 시험하지 않았다.**
  - 폴드8 펼친 화면을 반으로 나누면 앱 폭이 약 460dp라 커버 배치가 된다. 이 경우와 높이가 낮은 창을 시험해야 한다.
  - 위 2장의 '배치를 창 폭으로만 고른다'와 같은 작업이다.
- (중) **비교 보기가 없다.**
  - 삼성 갤러리는 펼친 화면에서 원본과 편집본을 나란히 보여 준다.
  - 넓은 펼친 화면을 살리는 다음 후보다.
- (소) **반 접기(테이블탑) 배치가 없다.**
  - 폴드8은 Flex 모드가 없어 효과가 없다.
  - 폴드8 울트라·아이폰 듀오에서 쓸모가 있다. 계획대로 맨 마지막이 맞다.
- (참고) **아이폰 듀오용 앱은 iOS로 따로 만들어야 한다.**
  - 엔진을 순수 Kotlin으로 떼어 둔 원칙(CLAUDE.md 3장)이 그때 쓰인다.
  - 애플 펜슬 규칙도 참고한다: 펜을 올리면 미리 보기만 하고, 두 번 톡은 사용자 설정을 따른다.

## 그 밖에 찾은 것

- 에뮬레이터(안드로이드 17)에서 사진을 열었더니 프로젝트 이름이 파일 이름 대신 '161' 같은 숫자로 보였다.
  - 사진 선택기가 파일 이름 대신 번호를 주는 것으로 보인다.
  - 폴드8에서도 그런지 확인해야 한다(결정 기록 '프로젝트 이름').

## 추천 순서

1. 작은 것: 하위 도구 아이콘 표시, 안내 알림 지우기, 프로젝트 이름 확인.
2. 폴드8에서 바로 느끼는 것: 높이가 낮은 창(커버 가로·창 나누기) 배치, 끌어 놓기, 세로 화면 패널 자리.
3. 태블릿 입력: 키보드 단축키 → 마우스 → S펜.
4. 손 닿는 범위: 실행 취소 위치, 왼손·오른손 설정.
5. 나중: 비교 보기, 테이블탑, 여러 창.
