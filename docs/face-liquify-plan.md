## 1. 지금 유동화 엔진(분석)

- 변형 저장 — `LiquifyMesh`(engine/liquify/LiquifyMesh.kt): 문서를 덮는 변위 격자. 꼭짓점마다 '이 자리 결과 픽셀을 원래 그림의 어디(문서 픽셀 dx, dy)에서 가져올지'를 둔다(거꾸로 찾는 방식). 칸은 4px 이상, 꼭짓점 40만 개 이하(50MP면 약 12px 칸), 꼭짓점 사이는 쌍선형으로 잇는다. 한 꼭짓점은 1000px까지.
- 계산: 브러시(뒤틀기·오목·볼록·재구성) 한 번마다 브러시가 닿는 꼭짓점만 Kotlin으로 고친다. 앞 변위를 이어 읽어 겹쳐 쌓고, 가장자리로 갈수록 (1 − (r/R)²)²로 약하다. 작업 창 안의 되돌리기는 획마다 격자 사본(8단계).
- 미리 보기: 고른 레이어 하나만 그린 축소본 + 격자를 반정밀도 그림(꼭짓점 하나 = 텍셀 하나)으로 GPU에 올려, AGSL 셰이더(`LiquifyRenderer`)가 화면 픽셀마다 변위를 읽어 원래 그림의 그 자리를 읽는다. 바뀔 때마다 한 번에(그리는 중이면 끝난 뒤 한 번 더) 다시 그린다.
- 적용: `LiquifyLayer(레이어, 격자 사본)` 명령이 움직인 곳(`changedBounds`)에 닿는 타일만 원본 해상도에서 1024px 묶음으로 같은 셰이더로 다시 그려 새 타일을 만들고, 나머지 타일은 앞 문서와 함께 쓴다 → 실행 취소 한 단계. HDR 게인맵도 같은 변위로. 결과는 픽셀로 굳고 다음에 열면 빈 격자에서 시작한다(지금은 다시 고칠 수 없음).

## 2. 얼굴 보정을 이 엔진에 붙이는 구조 (가능, 새 변형 엔진 없음)

- 얼굴 슬라이더 값 → 얼굴 변위(계산식) → 같은 `LiquifyMesh` 격자의 꼭짓점 값으로 → 지금의 미리 보기 셰이더·적용 명령 그대로. 새 셰이더·새 적용 경로 없음.
- 합치는 순서: 얼굴 보정을 원래 사진에 먼저, 손으로 민 것은 그 위(특징점을 원래 사진에서 찾으므로). 꼭짓점마다 결과에서 거꾸로 따라간다: y = q + m(q) → y += 얼굴형 변위(y) → y += 눈·코·입 변위(y) → 꼭짓점 값 = y − q. 부위 변형을 더하지 않고 차례로 이어 걸어, 겹치는 부위(눈 간격 + 눈 너비 등)에서도 접히지 않는다. 여러 얼굴은 하나씩 차례로.
- 얼굴 좌표계: 두 눈동자 가운데가 원점, 눈을 잇는 선이 가로축(얼굴이 기운 만큼 같이 기움), 턱 쪽 수직이 세로축, 크기 단위 U = 두 눈 사이 거리(고개를 돌려 좁아지면 원점–턱 거리의 반으로 받침). 눈·입·코는 저마다의 축(눈꼬리–눈머리, 입꼬리 둘)을 쓴다 → 기울어진 얼굴도 부위 방향대로.
- 미리 보기: 슬라이더를 끄는 동안 얼굴 부위 둘레의 꼭짓점만(얼굴 하나에 보통 1만~13만 개) 다시 계산해 지금의 그리기 흐름(그리는 중이면 끝난 뒤 한 번 더)에 넣는다. 화면의 얼굴 테두리는 바뀐 모습을 따라 그린다.
- 격자 촘촘함의 한계: 50MP는 칸이 약 12px라, 두 눈 사이가 칸 12개(약 150px)보다 작은 얼굴은 고르게 바뀌지 않을 수 있다 → 고칠 수는 있게 두고 안내. (더 필요하면 나중에 얼굴만의 작은 변위 그림을 셰이더에서 한 번 더 읽는 방법이 있다.)
- 부위별 계산식은 아래 '부위 계산'.

## 부위 계산(시작값, 폴드8에서 써 보고 고칠 수 있게 한곳에)

- 감쇠: 안쪽 t0까지는 1, 바깥 경계(t = 1)에서 정확히 0으로 매끈하게(5차 스무드스텝). t는 부위 축 기준 타원 거리.
- 기본 동작 넷: 늘이기·줄이기(부위 가운데 기준), 옮기기, 돌리기(10° 이하), 반쪽 늘이기(입술: 입선 한쪽만). 얼굴 윤곽은 '띠' — 윤곽 안쪽에서 1까지 올라 윤곽 바깥 좁은 띠(0.22~0.35U)에서 0.
- 슬라이더(−100~+100, + = 크게·위로·넓게·길게):

| 슬라이더 | 동작(쓰는 특징점) | 최대 |
| --- | --- | --- |
| 눈 크기·높이·너비 | 눈 가운데(눈 윤곽 16점 평균) 기준 늘이기, 크기는 양쪽·높이는 세로·너비는 가로 | 확대 22%·20%·15% |
| 눈 기울기 | 눈 가운데 기준 돌리기(+면 두 눈꼬리가 올라감, 좌우 자동 대칭) | 8° |
| 눈 간격 | 두 눈을 가로축으로 밖·안으로 옮기기 | 0.05U |
| 뒷트임 | 눈꼬리(33·263) 둘레를 눈꼬리 쪽으로 옮기기(눈 안쪽 반은 그대로) | 눈 폭의 13% |
| 코 높이 | 코(콧방울 129·358 가운데)를 세로로 옮기기 | 0.05U |
| 코 너비 | 콧방울 기준 가로 늘이기 | 22% |
| 콧등 너비(사용자 요청) | 콧등 가운데 줄(168·6·197·195·5) 기준 가로 늘이기. 눈머리(133·362)에 닿기 전에 0, 아래는 콧방울 위에서 0이라 코 너비와 겹치지 않음 | 20% |
| 미소 | 입꼬리(61·291)를 위·조금 바깥으로 | 입 폭의 6% |
| 윗입술·아랫입술 | 입선(13·14) 기준 바깥 입술(0·17) 쪽 반쪽 늘이기 | 35% |
| 입 너비 | 입 가운데 기준 가로 늘이기 | 15% |
| 입 높이 | 입을 세로로 옮기기 | 0.05U |
| 이마 | 눈썹 줄~이마 끝(10) 띠를 위·아래로 | 0.08U |
| 턱 높이 | 아랫입술(17)~턱 끝(152) 띠를 아래·위로 | 0.08U |
| 턱선 | 턱 모서리(172·397)를 바깥·안으로 | 0.06U |
| 얼굴 너비 | 볼·턱 윤곽 띠를 가로축으로만 안·밖으로(가운데 줄 둘레는 0이라 이음매 없음, 턱 끝 가까이에서 0) | 0.06U |

- 특징점 번호는 1단계의 번호 표시 화면으로 맞는지 확인한다(미디어파이프 478점 표).
- 배경 휨 줄이기: 눈·코·입은 얼굴 윤곽 안에서 끝나 배경에 닿지 않는다. 윤곽을 바꾸는 넷(이마·턱 높이·턱선·얼굴 너비)은 한 축으로만 옮기고(얼굴 너비는 가로축만이라 눈선과 나란한 배경 선은 곧게 남음), 윤곽 밖 띠를 좁게(0.22~0.35U), 늘어나는 정도를 반 이하로, 움직임은 0.08U 이하로 묶고, 부위 상자 밖은 정확히 0이다(시험으로 확인). 윤곽 바로 옆 좁은 띠의 배경은 조금 휠 수밖에 없다(포토샵도 같다). 배경을 고정해 칠하는 마스크(포토샵 '고정 마스크')는 나중 후보.
- 고개를 많이 돌린 얼굴은 먼 쪽 부위를 약하게(약 50°를 넘으면 끔) — 마무리 단계에서.

## 3. 얼굴 인식 — 승인이 필요한 것

- 제안: 미디어파이프 Face Landmarker의 '모델 파일'만 받아 지금 쓰는 LiteRT 2.2.0으로 돌린다. 새 라이브러리 없음, 인터넷 권한 없음.
  - 미디어파이프 라이브러리(Tasks)는 따라오는 구글 전송 부품(DataTransport)이 INTERNET·ACCESS_NETWORK_STATE 권한을 붙이고 앱이 약 14MB 커진다(이 프로젝트 조사, docs/ai-remove-research.md). ML Kit 얼굴 윤곽(133점)도 같은 전송 부품·사용 통계가 있어 '인터넷·분석 없음'에 어긋난다. dlib(68점)·InsightFace 등은 모델·학습 데이터가 비상업 허락이다. → 478점·Apache-2.0·작은 FaceMesh가 가장 맞다.
- 모델(두 파일, 모두 Apache-2.0, 모델 카드 확인):
  - 얼굴 찾기: BlazeFace 먼 거리용 `blaze_face_full_range.tflite` 1,083,786바이트(float16) — 후면 카메라 사진, 5m까지, 여러 얼굴(10개까지). (짧은 거리용 229,746바이트는 셀카용이라 쓰지 않음)
  - 특징점: FaceMesh V2 — `face_landmarker.task`(3,758,596바이트) 묶음에서 `face_landmarks_detector.tflite`만 꺼낸다(묶음의 짧은 거리 얼굴 찾기·표정 모델은 안 씀). 256×256 입력, 478점(눈·홍채·입술·얼굴 윤곽), 얼굴 있음 점수.
  - 앱이 커지는 양: 약 3.6MB(특징점 파일의 정확한 크기는 내려받아 확인, 약 2.5MB 예상). 지금 디버그 APK 약 174MB.
  - 출처: storage.googleapis.com/mediapipe-models(구글 공식). git에 넣고 `LICENSE-FACE.txt`(출처·크기·SHA-256)와 설정의 오픈소스 고지에 더한다(MI-GAN·SAM과 같은 방식).
- 대가: 미디어파이프가 해 주던 앞뒤 처리를 Kotlin으로 짠다(공개 소스의 값 그대로: 입력 192×192 비율 유지, 앵커 2304개, 점수 시그모이드, IoU 가중 NMS / 특징점은 눈으로 돌려 1.5배 정사각형으로 잘라 256×256, 두 번째로 눈꼬리 33·263으로 다시 맞춤, 좌표 되돌리기). 순수 Kotlin이라 JVM 테스트로 확인.
- 돌리는 곳: 두 모델 모두 작아 CPU로 먼저(4스레드), 안 되면 GPU. 지금처럼 AI 스레드 하나(`stratum-ai`)에서만. 불러올 때 입력·출력 모양을 확인한다(얼굴 찾기 2304×16·2304×1, 특징점 1434·1).
- 작은 얼굴: 사진 전체 한 번(192×192)만 보면 단체 사진의 작은 얼굴(긴 변의 약 5% 미만)을 놓친다 → 긴 변 약 2048px로 그려 3×3 조각(25% 겹침)으로 한 번 더 찾고 합친다. 두 눈 사이가 24px보다 작은 얼굴은 뺀다. 얼굴은 8개까지.
- 찾는 그림: 유동화하는 레이어 하나만(유동화 미리 보기와 같은 레이어), 다시 열 때는 유동화 전 원래 픽셀.
- 모델 카드의 한계: 고개를 많이(80° 넘게) 돌렸거나, 반 넘게 가려졌거나, 아주 작은(먼) 얼굴은 못 찾을 수 있다 → '얼굴을 찾지 못했어요' 안내.

## 4. 저장 방식(다시 고치기)

- 레이어에 '유동화 기록'(새 속성 `Layer.liquify`, 글자 레이어의 글자 정보와 같은 방식): 유동화 전 원래 픽셀(타일을 함께 써서 바뀐 타일만 메모리) + 원래 게인맵 + 손으로 민 격자(없으면 비움) + 얼굴마다(찾은 특징점 478개 + 슬라이더 값) + 계산식 판 번호. 레이어 픽셀은 적용한 결과라 그리기·내보내기·병합·AI 선택·썸네일은 지금과 같다.
- 다시 열면 그 기록에서 이어서 고친다. 특징점은 다시 찾지 않는다(앱·모델이 바뀌어도 고친 값이 움직이지 않게). 적용하면 원래 픽셀에서 다시 계산하므로, 값을 0으로 되돌린 곳은 원래 타일로 돌아간다. 모두 0이면 기록을 지우고 원래 픽셀로(실행 취소 한 단계).
- 프로젝트 파일: 레이어 덧붙임 꼬리표 5(원래 픽셀 타일 목록 + 원래 게인맵 + 얼굴 값, 얼굴 하나에 약 4KB), 격자는 바뀐 범위만 따로 파일(`liquify/…mesh`, 목차에 넣지 않음). 기록의 파일이 없거나 깨졌으면 기록만 버리고 프로젝트는 연다(앞 판 앱이 저장하며 원래 픽셀 타일을 지울 수 있으므로). 앞 판 앱은 모르는 꼬리표라 결과 픽셀로 연다.
- 실행 취소 기록 메모리·저장 크기 어림에 원래 픽셀 타일을 함께 센다.
- 지우는 때(굳히기): 픽셀을 바꾸는 다른 명령은 모두 기록을 지운다(`withPixels`·`withText`, 글자 정보와 같이 — 빠뜨려도 기록이 조용히 사라질 뿐, 픽셀과 어긋난 기록이 남지는 않는다). 묻지 않는다(사용자 결정): 칠하는 도구·이동 도구로 기록이 있는 레이어를 바꾸면 바로 굳히고 짧은 알림('유동화를 픽셀로 굳혔어요, 다시 고칠 수 없어요')을 한 번 보인다. 실행 취소로 되돌리면 기록도 돌아온다. 이미지 전체 자르기·회전·뒤집기·크기 변경·병합도 굳힌다. 레이어 복제는 기록도 복제한다. 글자 레이어의 '먼저 묻기'는 그대로다.
- 레이어 줄: 기록이 있는 레이어에 작은 표시(글자 표시처럼), 레이어 메뉴 '픽셀로 바꾸기'로 직접 굳힐 수도 있다(Claude 판단).
- 작업 창 안 되돌리기: 한 단계 = (격자, 얼굴 값). 획 하나, 슬라이더를 놓을 때, 두 번 톡 초기화, '얼굴 초기화'가 각각 한 단계(지금처럼 8단계까지). '모두 되돌리기'는 격자와 얼굴 값 모두.

## 5. 화면

- 유동화 작업 화면의 도구 줄에 '얼굴'(Material Icons face_retouching_natural) 하나를 더한다: 커버는 맨 아래 [X | 뒤틀기·오목·볼록·재구성 | 얼굴 | ✓], 커버 가로는 같은 세로 기둥, 펼친 화면은 띠의 도구 칸. 엔진의 브러시 도구 목록(`LiquifyTool`)은 그대로 두고 화면 쪽 모드로 더한다.
- 얼굴 모드를 처음 고르면 얼굴을 찾는다(처리 중 막대). 하나면 바로 고르고, 여럿이면 얼굴마다 테두리를 보이고 톡해서 고르며(고른 얼굴은 강조), 없으면 '얼굴을 찾지 못했어요' 알림(유동화 창 안의 알림, 사진 레이어를 골랐는지 함께 안내).
- 얼굴 모드에서 캔버스를 누르면 칠하지 않고 얼굴만 고른다(손가락이 움직이지 않은 톡만). 두 손가락 확대·이동·톡은 그대로.
- 슬라이더: 가운데 0인 ± 슬라이더(조정 패널의 슬라이더 줄을 함께 쓰는 부품으로 꺼냄, 원을 두 번 톡하면 0, 화면 읽기 '초기화'), 끄는 동안 미리 보기, 놓으면 작업 창 되돌리기 한 단계.
  - 커버: 한 줄 막대에 [얼굴 n ▾(여럿일 때)] [부위 ▾ 눈·코·입·얼굴형] [그 부위의 슬라이더 칩, 바뀐 칩은 점] [얼굴 초기화] — 칩을 누르면 그 줄이 ± 슬라이더 한 줄(커버 조정 `adjustBar`와 같은 모양). 커버 가로는 세로 슬라이더(가운데 0).
  - 펼친 화면: 프로젝트 규칙대로 띠에 [도구 칸 | 얼굴·부위 고르기 칸 | 그 부위의 슬라이더 칸(누르면 가운데 0인 세로 슬라이더 창) | 얼굴 초기화]. 펼친 화면 띠·슬라이더는 만들 때의 펼친 화면 방식을 따른다(계획할 때 12차가 바꾸던 중이었다).
- 두 눈은 한 슬라이더로 함께 고친다(좌우 따로는 나중 후보, Claude 판단). 부호는 + = 크게·위로·넓게·길게(코·입 높이 + = 위로, 턱선 + = 넓게, Claude 판단).
- 1단계 확인용: 고른 얼굴 위에 478점, 얼굴 좌표축, 계산에 쓰는 특징점의 번호를 그린다. 2단계부터는 얼굴 테두리만 보인다(점은 숨김).
- 문구는 모두 `values/`·`values-ko/` 두 언어.

### 1. 얼굴 찾기 + 특징점 표시(확인용)
- 엔진 순수 Kotlin `engine/face/`: 앵커·풀기·NMS(`FaceDetectionDecoder`), 자를 곳·좌표 되돌리기(`FaceRoi`), 모델 입력(`FaceTensor`), 결과(`FaceLandmarks`, 특징점 번호표 `FaceMeshIndex`), 모델 틀(`FaceModel`·`FaceUnavailableException`).
- 엔진 플랫폼: `LiteRtFaceModel`(AI 스레드, CPU 먼저, 빈 그림 확인, 모양·시간 기록), `FaceFinder`(레이어 하나를 `PreviewRenderer`로 그려 전체 + 3×3 조각 찾기 → 특징점 두 번 → 문서 좌표). `LiteRtSegmentModel`·`ObjectSegmenter`와 같은 틀(불러오기·내려놓기 `releaseAiModels`, 메모리 어림, 쓸 수 없는 기기 알림).

- 테스트: JVM(앵커 2304개·첫 앵커 자리, 합성 텐서 풀기, NMS, 30° 기운 눈으로 자를 곳, 자름↔문서 왕복, 비율 유지 여백), 에뮬레이터 `FaceModelProbeTest`(CPU 불러오기·출력 크기·빈 그림은 얼굴 없음), `FacePhotoTest`(시험 사진: 얼굴 수, 90°·30° 돌린 사본에서 특징점도 같이 돎, 없으면 건너뜀), 화면 테스트(톡해서 고르기·못 찾음 알림·얼굴 칸).

### 2. 슬라이더 3개(눈 크기·코 너비·얼굴 너비) + 미리 보기 + 적용
- 엔진 순수 Kotlin: `face/FaceWarp`(감쇠·기본 동작·차례로 걸기·부위 상자, 18개 계산식을 처음부터 한곳에 두되 화면에는 셋만), `liquify/FaceComposer`(꼭짓점 범위 채우기, 손 격자와 합친 최종 격자, 테두리용 순방향 따라가기).
- 앱: 슬라이더 값·작업 창 되돌리기 단계, 그리기 흐름에 합치기, 적용할 때 최종 격자로 `LiquifyLayer`(실행 취소 한 단계, 이 단계에서는 아직 굳힘). 커버 칩·띠 칸, 가운데 0 슬라이더 부품.
- 테스트: JVM(모두 0이면 변위 0, 부위 상자 밖 0, 슬라이더마다 방향, 얼굴을 37° 돌리고 0.5배여도 같은 결과, 접힘 없음(야코비안 > 0.3, ±100%·모두 켬), 가운데 줄 이음매 없음, 최대량, 띠 밖 배경 선 그대로, 손 격자와 합치기), 앱(가짜 얼굴 찾기로: 놓을 때마다 되돌리기 한 단계, 적용은 기록 한 단계, 취소는 그대로), 화면(커버·펼친·커버 가로).

- 에뮬레이터에서 볼 것: 적용 → 다시 열기 → 값 고치기 → 적용(실행 취소 한 단계), 앱을 끄고(백그라운드 종료) 다시 열어도 고칠 수 있음, 그 레이어를 브러시로 칠하면 굳힘 알림이 뜨고 실행 취소하면 다시 고칠 수 있음.
