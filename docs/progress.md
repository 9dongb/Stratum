# 작업 현황

CLAUDE.md가 이 파일을 불러오므로, Claude Code는 세션을 시작할 때마다 이 파일을 읽는다.
어느 PC에서 받아도 여기서부터 이어서 작업할 수 있게, **지금 상태만 짧게** 적는다.
끝난 작업의 자세한 내용은 `docs/history.md`(작업 이력)에 쌓는다.

사용자의 요청과 의도는 가능하면 사용자의 말 그대로 적는다. 사용자가 말하지 않은 의도는 짐작해서 쓰지 않는다.

마지막 갱신: 2026-10-17

## 진행 중

- **이 PC로 옮겨 온 뒤 환경 확인과 기록 보충** (시작: 2026-10-17)
  - 요청: 지금 상태 요약, 이 PC의 개발 환경 확인("문제가 있으면 고치기 전에 알려줘"), "맥락의 1번으로 docs/history.md의 "기록 없음" 칸을 채우고, 3번 에뮬레이터 확인 요령 중 어느 PC에서나 쓸 내용은 저장소 문서로 옮겨줘", 다음 작업 후보 안내
    - 계획을 본 뒤: "계획대로 진행해줘. gradlew 실행 권한 수정과 문서 정리 둘 다 해줘."
  - 의도: 말하지 않음
  - 한 일: 상태 요약, 환경 확인(빌드·테스트 통과, Pixel_Fold는 사용자가 만듦), `gradlew` 실행 권한 수정
  - 남은 일: 문서 정리(history.md 빈칸, `docs/emulator.md`, 이 파일의 결정 기록), 다음 작업 후보 안내

진행 중인 일은 아래 형식으로 적는다.

```
- **작업 제목** (시작: 날짜)
  - 요청: 사용자가 요청한 것
  - 의도: 사용자가 말한 목적. 말하지 않았으면 "말하지 않음"
  - 한 일 / 남은 일
```

다음 후보(순서는 아직 정하지 않음): 사진 선택기(Photo Picker) 연결, 새 캔버스 시트, 화면 크기별 레이아웃·힌지 피하기

작업 도중 다른 PC로 옮길 때는 여기에 어디까지 했고 무엇이 남았는지 적은 뒤, 빌드가 되는 상태로 커밋해서 push한다.

## 결정 기록

사용자가 정한 것이다. 바꿔야 하면 먼저 묻는다.
각 결정에는 이유를 붙인다. 사용자가 추천안을 골랐으면 "추천 수용"이라고 표시하고, 이유를 모르면 "기록 없음"이라고 쓴다.

- **작업 기록:** 지금 상태는 이 파일에, 끝난 작업은 `docs/history.md`에 적는다.
  - 의도(사용자): "푸시 후에 다른 피시에서 이를 받아 작업을 이어해도 문제 없도록 작업 현황이나 맥락을 기록"
  - 의도(사용자): "작업 이력을 쌓고, 진행 중인건 기록"
  - 의도(사용자): "이력과 진행상황 기록 시 내 의도도 함께 기록"
- **실행 취소 방식:** 명령마다 결과 문서를 보관한다(이전 상태 보관), 최대 50단계. 문서·레이어·타일은 바꾸지 않고, 바뀌지 않은 부분은 이전 상태와 공유한다.
  - 이유(CLAUDE.md 4장): 매번 전체 이미지를 복사하지 않고 바뀐 타일만 메모리를 쓴다. 나중에 '작업 내역 브러시'에 그대로 쓸 수 있다.
- **화면 이동:** 라이브러리 없이 `AppScreen`(홈·편집) 값과 `rememberSaveable`, `BackHandler`로 만든다(`ui/StratumApp.kt`). 화면은 홈·편집·설정뿐이고, 나머지는 시트·패널로 띄운다.
  - 이유(추천 수용): 화면이 3개뿐이라 이것으로 충분하고, 새로 배울 것과 설정이 늘지 않는다.
- **기능이 없는 버튼:** 숨기지 않고 제자리에 비활성으로 둔다. 단, 커버 화면 도구 탭의 2·3단계 도구는 CLAUDE.md 8장대로 숨긴다.
  - 이유(추천 수용): 버튼 위치를 미리 확인할 수 있고, 기능이 생기면 켜기만 하면 된다.
- **앱으로 돌아올 때:** 새로 실행하면 항상 홈이다. 접기·펼치기나, 안드로이드가 백그라운드에서 앱을 종료했다가 돌아오면 보던 화면을 복원한다.
  - 이유(추천 수용): 앱이 몰래 종료됐든 아니든 돌아오면 늘 같은 화면이라 헷갈리지 않는다.
- **화면 확인:** 당분간 실기기 대신 에뮬레이터(Medium_Phone_API_37.0, Pixel_Fold)로 확인한다. 한 번에 하나만 켠다.
  - 이유: 기록 없음
- **저장소:** GitHub `9dongb/Stratum`(공개). 사용자가 직접 만들어 주소를 알려 줬다. push는 사용자가 요청할 때만 한다.

## 작업 전에 물어볼 것

아직 정하지 않았다. 해당 작업을 시작할 때 사용자에게 묻는다.

- **사진 열기 전:** 원본 해상도 픽셀을 어디에 둘지
  - A: 원본 타일은 자바 힙 밖에 두고, 화면에는 축소본(프록시)을 쓴다.
  - B: 축소본이 문서이고, 내보낼 때 명령을 원본 해상도로 다시 적용한다.
  - 제약: 50MP 레이어 하나가 약 200MB라, 힙의 `IntArray` 타일에는 축소본 크기만 들어간다.
- **기본 보정 전:** 1단계 기본 보정을 픽셀을 바꾸는 방식으로 할지, 값만 기록하는 방식으로 할지
- **자동 저장 전:** 실행 취소 기록을 앱을 다시 켠 뒤에도 남길지

## 설계 메모

해당 작업을 할 때 지킨다.

- **자동 저장:**
  - 백그라운드 종료 뒤 편집 화면이 복원되면, 열려 있던 프로젝트를 다시 불러와야 한다.
  - 그래서 프로젝트 id를 `rememberSaveable`이나 `SavedStateHandle`에 저장한다. 안 하면 빈 편집 화면이 보인다.
- **저장 형식:** `BlendMode`는 순서(ordinal)나 이름이 아니라 고정된 코드 값으로 저장한다.
- **버튼 켜기:**
  - 실행 취소·다시 실행 버튼은 `EditHistory.canUndo`·`canRedo`로 켠다.
  - 내보내기 버튼은 내보내기 작업 때 켠다.
- **레이어 패널:** 선택한 레이어는 ViewModel에 둔다. 실행 취소·다시 실행 뒤에는 그 레이어가 아직 있는지 확인한다.
- **슬라이더:**
  - 끄는 동안에는 `command.applyTo(history.document)` 결과만 보여 주고 기록하지 않는다.
  - 손을 떼면 `history.execute`를 한 번 부른다.
- **브러시:** `EditHistory`에 메모리(바이트) 한도를 더한다. 단계 수 제한만으로는 메모리 사용량이 묶이지 않는다.
- **캐시:** 썸네일·GPU 텍스처는 `LayerId`가 아니라 `Raster`·`Tile` 객체를 기준으로 한다. 실행 취소 뒤 레이어 번호가 다시 쓰이기 때문이다.
- **홈 최근 프로젝트:** 썸네일 격자는 `LazyVerticalGrid`로 만든다. 지금의 세로 스크롤 `Column` 안에 넣으면 높이가 무한대라 오류가 난다.

## 기술 주의점

- material3 1.4.0의 `TopAppBar`는 `@OptIn(ExperimentalMaterial3Api::class)`가 필요하다. 매개변수 타입 `TopAppBarScrollBehavior`가 실험 기능이기 때문이다.
- 아이콘은 Android Studio 'Vector Asset'의 Material Icons 파일을 쓰고, `android:tint="?attr/colorControlNormal"` 줄은 뺀다. 이 프로젝트에는 AppCompat이 없어서 그 줄이 있으면 빌드가 실패한다.
- `List.removeFirst()`·`removeLast()`는 안드로이드 13·14 기기에서 오류가 나므로 `removeAt(0)` 등을 쓴다.
- Gradle 9.6은 JDK 25로 실행한다. PC의 기본 java가 오래되었으면, 명령마다 `JAVA_HOME`을 Android Studio 내장 JDK(`jbr` 폴더)로 지정한다.
