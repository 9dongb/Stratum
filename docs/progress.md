# 작업 현황

CLAUDE.md가 이 파일을 불러오므로, Claude Code는 세션을 시작할 때마다 이 파일을 읽는다.
어느 PC에서 받아도 여기서부터 이어서 작업할 수 있게, **지금 상태만 짧게** 적는다.
끝난 작업의 자세한 내용은 `docs/history.md`(작업 이력)에 쌓는다.

사용자의 요청과 의도는 가능하면 사용자의 말 그대로 적는다. 사용자가 말하지 않은 의도는 짐작해서 쓰지 않는다.

마지막 갱신: 2026-10-18

- **작업 제목** (시작: 날짜)

  - 의도: 사용자가 말한 목적. 말하지 않았으면 "말하지 않음"
  - 한 일 / 남은 일

작업 도중 다른 PC로 옮길 때는 여기에 어디까지 했고 무엇이 남았는지 적은 뒤, 빌드가 되는 상태로 커밋해서 push한다.

  - 항목 하나 초기화는 이름을 두 번 누른다(라이트룸과 같음, 화면 읽기 기능은 '초기화' 동작). '모두 초기화' 버튼도 둔다. 둘 다 실행 취소 한 단계다.
  - 곡선: 점을 끌면 옮기고, 빈 곳을 끌면 그 자리 곡선 위에 점을 더해 끌고, 톡 누르면 점만 더한다. 고른 점 지우기·곡선 초기화 버튼을 옆에 둔다. 양 끝 점도 옮길 수 있다(지울 수는 없음).
  - 자르기 중에는 보정을 막는다. 이유: 기록하면 문서가 바뀌어 자르기 테두리가 처음으로 돌아간다(내보내기도 자르기 중에는 막음).
  - 다른 편집을 처리하는 동안 놓은 값은 끝난 뒤 기록하고, 그사이 다시 끌면 합쳐 한 단계로 기록한다. 끄는 도중 접기·펼치기로 배치가 바뀌면 놓은 것으로 보고 기록한다. 이유: 놓은 값을 잃지 않는다.
  - 메인 세로 아래 패널의 탭은 도구 고르기와 따로 기억한다. 커버에서 조정을 고른 채 펼치면 조정 탭을 보인다.
  - 메인 가로에서 도구(자르기·변형, 브러시, 지우개, 글자)를 고르면 오른쪽 패널의 조정 칸을 접어 둔다(칸 제목을 누르면 펼침). 도구를 고른 동안과 아닌 동안의 펼침은 따로 기억한다. 이유: 6번 확인 때 실제 앱에서 옵션·조정·레이어 세 칸이 나눠 좁았다. 도구를 쓰는 동안에는 옵션과 레이어를 더 본다.
- **레이어 패널(Claude 판단):** 기획서 '커버에서는 레이어 패널을 숨기고, 필요할 때 아래에서 올라오는 시트로 연다'와 CLAUDE.md 6장을 따른다.
  - 커버: 아래 탭 줄의 '레이어'를 누르면 캔버스 아래 옵션 자리에 버튼 줄(더하기·지우기·위로·아래로), 목록(세 줄까지 보이고 밀어 봄), 불투명도, 혼합 모드.
  - 메인 세로: 아래 패널의 '레이어' 탭. 왼쪽은 목록, 오른쪽은 불투명도·혼합 모드, 버튼 줄은 탭 줄 오른쪽.
  - 메인 가로: 오른쪽 패널의 '레이어' 칸. 조정 칸과 높이를 반씩 나누고, 칸 제목의 접기 버튼으로 접으면 다른 칸이 그 자리를 쓴다. 이유: CLAUDE.md 6장 '조정은 넣었다 뺄 수 있다'를 지금 있는 두 칸으로 한 것이다(채널·작업 내역 탭은 그 기능이 생길 때).
  - 목록은 위 레이어가 위다(포토샵과 같다). 줄: 작은 그림, 이름, 혼합 모드·불투명도, 순서 손잡이. 고른 줄은 바탕을 칠한다.
  - 순서 바꾸기는 손잡이를 위아래로 끌거나 위로·아래로 버튼(화면 읽기 기능의 '위로'·'아래로' 동작도). 이유: 터치 앱에서 흔한 끌기와, 한 칸씩 정확히 옮기는 버튼을 함께 둔다.
  - 새 레이어는 고른 레이어 바로 위에 빈 레이어로 더하고 고른다. 이름은 '레이어 N'(N은 문서의 다음 레이어 번호). 포토샵과 같다.
  - 지우기는 고른 레이어를 묻지 않고 지우고(실행 취소로 되돌림) 그 아래 레이어를 고른다. 마지막 한 장은 지우지 않는다.
  - 불투명도는 0~100% 슬라이더로, 끄는 동안 미리 보고 놓으면 기록한다(보정과 같다). 혼합 모드는 버튼을 누르면 표준·곱하기·스크린·오버레이 메뉴다.
  - 혼합 계산은 W3C 합성 규격·포토샵과 같은 공식이고, 감마를 풀지 않은 sRGB 값에서 섞는다. JPEG의 흰 바탕은 섞은 뒤에 깐다(화면에 보이는 것과 같게).
  - 작은 그림은 레이어 픽셀에 보정을 건 것이다(불투명도·혼합 모드는 빼고). 레이어별 축소본을 줄여 만들어 큰 사진도 타일을 다시 읽지 않는다.
  - 이름 바꾸기는 하지 않았다. 이유: CLAUDE.md 8장 1단계 목록에 없다. 복제·합치기와 숨기기(눈)는 사용자가 요청해서 더했다(결정 기록 '레이어 메뉴'·'레이어 보이기').
- **브러시·지우개(Claude 판단):**
  - 둥근 브러시 하나다. 크기(1~1000px, 작은 크기를 세밀하게 고르도록 로그 눈금), 단단함(0~100%), 불투명도(1~100%), 색(팔레트·최근 색, 결정 기록 '색 팔레트·최근 색')을 고른다.
  - 지우개는 같은 모양으로 고른 레이어를 투명하게 지운다. 브러시와 지우개 설정은 따로 기억한다(앱을 끌 때까지).
  - 한 획의 불투명도는 자국이 겹쳐도 넘지 않는다(포토샵의 불투명도와 같다). 흐름(flow)·필압·떨림 보정·브러시 모양 고르기·스포이트는 나중에 한다.
  - 고른 레이어에 그린다. 한 손가락으로 그리고, 두 번째 손가락이 닿거나 두 손가락 조작이 시작되면 끄던 획을 버린다. 이유: 두 손가락 확대·이동과 섞이지 않게 하는 흔한 방식(Procreate 등)이다.
  - 손을 떼면 실행 취소 한 단계로 기록한다. 앞 획을 기록하는 동안에도 다음 획을 그릴 수 있고, 차례로 기록한다. 이유: 빠르게 여러 번 그어도 획을 잃지 않는다.
  - 끄는 동안의 미리 보기는 축소본에 GPU로 그린다. 확대해 보는 중이면, 맨 위 표준 레이어(불투명도 100%, 보정 없음)에 그릴 때는 확대 그림 위에도 그려 선명하게 보인다. 그 밖에는 끄는 동안 축소본이 보이고 손을 떼면 다시 선명해진다.
  - 원본 해상도 타일에는 안드로이드 소프트웨어 그리기로 그린다. CLAUDE.md 2장 'GPU 우선'과 다르다(최종 보고에서 알린다).
    - 이유: 획이 닿지 않은 픽셀이 조금도 바뀌지 않는다. GPU는 값이 1/255씩 달라질 수 있어(결정 기록 '회전·뒤집기·자르기는 안드로이드 내부 복사' 때 확인) 같은 곳에 여러 번 그리면 쌓인다.
    - Kotlin으로 픽셀을 하나씩 돌지 않는다(안드로이드가 그린다). 획이 닿는 타일만 그린다.
- **글자(Claude 판단):**
  - 글자 도구를 고르고 캔버스를 누르면 글자 창이 뜬다. 넣으면 누른 자리(글자의 왼쪽 위)부터 고른 레이어 바로 위의 새 레이어로 그린다. 레이어 이름은 글자 첫 줄(앞 20자)이다.
  - 색(팔레트·최근 색, 브러시와 같은 색 줄)과 크기(8~2000px, 처음에는 문서 짧은 변의 6%)를 고른다. 글꼴은 기기 기본(한글 포함)이고 여러 줄은 왼쪽에 맞춘다.
  - 글자는 픽셀로 그려 넣는다. 다시 고칠 수 있는 글자 레이어, 글꼴 고르기, 넣은 뒤 옮기기는 나중에 한다. 이유: CLAUDE.md 8장 '텍스트 기본'이고, 옮기기는 이동 도구(2단계 선택 도구와 함께)가 필요하다.
- **설정 화면(Claude 판단):** 기획서 화면 목록 '설정'(미리보기 해상도(성능), 기본 내보내기 형식, 제스처, 앱 정보, 커버는 목록·메인은 2단)을 따른다.
  - 바꾸면 바로 저장한다(저장 버튼 없음). 안드로이드 기본 저장소(SharedPreferences)에 둔다. 이유: 새 라이브러리 없이 되고 값이 몇 개뿐이다.
  - 메인 2단: 메인 가로는 세로 힌지 양쪽에 분류와 항목을 놓는다. 메인 세로는 가로 힌지의 띠에 걸리는 분류 줄·항목을 띠 아래로 비켜 놓는다(스크롤하면 내용과 함께 움직인다, '홈 최근 프로젝트'와 같은 까닭). 커버는 힌지를 보지 않는다.
  - 내보내기 기본값(형식·품질·크기): 앱을 켜면 내보내기 창이 이 값으로 시작하고, 같은 실행에서 내보낸 뒤에는 마지막 고르기가 이어진다. 이유: 기본값과 '마지막 값 기억'을 함께 쓰는 흔한 방식이고, 내보내기 때 만든 '앱을 끌 때까지 기억'을 그대로 둔다.
  - 미리 보기 화질: 표준(기본) / 가볍게. 가볍게는 화면보다 큰 사진의 전체 축소본을 한 단계(가로·세로 반) 작게 그리고, 맞춤으로 볼 때는 그대로 두며, 확대하면 지금처럼 선명하게 다시 그린다. 문서를 열 때 읽는다. 이유: 큰 사진에서 슬라이더·브러시 미리 보기가 그리는 픽셀이 1/4로 준다. 설정은 홈에서만 열려 열린 문서가 없다.
  - 두 손가락으로 톡: 실행 취소(기본 켬). 두 손가락이 닿은 뒤 어느 손가락도 터치 허용 거리만큼 움직이지 않고, 처음 닿은 지 0.35초 안에 모두 떼면 된다. 실행 취소 버튼이 켜져 있을 때만 된다. 이유: Procreate·포토샵(iPad)과 같은 흔한 제스처이고, 캔버스 확대·이동 때 이 자리를 비워 두었다(결정 기록 '캔버스 확대·이동'). 세 손가락 톡(다시 실행)은 하지 않았다.
  - 앱 정보: 버전, 개인정보(인터넷을 쓰지 않음·광고·로그인·분석 없음), 오픈소스 라이선스(쓰는 AndroidX·Compose·Kotlin·코루틴·Material 아이콘, 모두 Apache 2.0을 적은 글). 이유: 라이선스 화면을 만드는 라이브러리(oss-licenses)를 새로 쓰지 않는다.
- **선택 도구(Claude 판단):** 사용자가 2단계 기능(선택 도구)을 요청해서 만든다(CLAUDE.md 8장 '사용자가 요청하기 전에 만들지 않는다').
  - 선택 영역은 문서 크기의 알파 마스크다(0 고르지 않음 ~ 255 다 고름). 타일(256px, 픽셀당 1바이트, 힙 밖 알파 비트맵)로 두고, 다 고른 타일은 한 장을 함께 쓴다. 경계 타일만 메모리를 쓴다.
  - 선택 영역은 문서의 일부라 실행 취소 기록에 남는다(고르기·풀기가 한 단계). 프로젝트 파일에는 저장하지 않아 다시 열면 없다. 이유: 포토샵도 선택 영역은 따로 저장하지 않으면 남지 않고, 저장 형식이 단순하다.
  - 하위 도구: 사각형·원형(끈 사각형에 맞는 타원, 꼭짓점은 픽셀 경계에 맞춤), 올가미(손가락 길을 닫은 모양, 두 번 감싼 곳은 밖), 자동 선택(마술봉).
  - 합치는 방법: 새로(기본)·더하기·빼기·교차(포토샵과 같은 네 가지). 페더는 0~250px(경계를 흐림, 사각형·원형·올가미).
  - 자동 선택: 고른 레이어를 보정을 건 모습으로, 긴 변 2048px 이하로 줄여 그린 그림에서 비슷한 색을 찾고 원본 크기로 부드럽게 키운다. 허용치 0~255(기본 32, 포토샵과 같음), 이어진 곳만(기본 켬).
    - 이유: 이어진 곳 찾기(채우기)는 GPU로 하기 어렵고, 원본(50MP)에서 Kotlin으로 픽셀을 돌면 CLAUDE.md 2장에 어긋난다. 그래서 줄인 그림(약 4MP 이하)에서만 돈다(최종 보고에서 알린다). 큰 사진은 경계가 줄인 만큼(50MP는 4px 안쪽) 덜 정확하다.
  - 고른 곳의 효과: 브러시·지우개는 고른 곳에만 그린다(부드러운 경계는 그만큼 옅게). 보정·글자·레이어 속성은 선택과 상관없이 레이어 전체다. 일부만 보정하려면 '새 레이어로 복사' 뒤 그 레이어를 보정한다(레이어 마스크는 아직 없다).
  - 동작: 모두 선택, 해제, 반전, 지우기(고른 레이어의 고른 곳을 투명하게), 새 레이어로 복사·잘라내기(바로 위에 새 레이어, 원래 레이어의 불투명도·혼합 모드·보정을 그대로 가져가 같아 보임, 끝나면 선택을 푼다 — 포토샵과 같다).
  - 캔버스를 끌지 않고 누르기만 하면(새로 고르기일 때) 선택을 푼다(포토샵과 같다). 두 손가락 조작이 시작되거나 두 번째 손가락이 닿으면 끄던 모양을 버린다(브러시와 같다).
  - 자르기·회전·뒤집기·크기 변경을 하면 선택이 풀린다. 이유: 구조가 단순하다(포토샵은 함께 옮긴다).
  - 윤곽선(개미 행렬): 줄인 마스크(긴 변 1024px)에서 반쯤 고른 곳을 따라 찾고, 확대해 볼 때는 보이는 곳을 확대 단계로 다시 찾는다(부분 그림과 같은 자리). 흰 선 위에 검은 점선이 흐른다. 어떤 도구를 골라도 보인다.
    - 윤곽선 찾기도 줄인 마스크에서만 Kotlin으로 돈다(자동 선택과 같은 까닭).
  - 도구 자리: 메인 도구 막대는 자르기·변형 다음, 커버 탭 줄은 조정 다음. 아이콘은 Android Studio 'Vector Asset'의 Material Icons(highlight_alt 등)다.
  - 옵션: 하위 도구 줄, 합치는 방법 줄, 페더(제곱 눈금) 또는 허용치·이어진 곳만, 동작 버튼 6개(모두·해제·반전·지우기·복사·잘라내기, 화면 읽기 기능은 긴 이름으로 읽음), 안내 한 줄. 설정은 앱을 끌 때까지 남는다(브러시와 같다).
- **픽셀 유동화(Claude 판단):** 사용자가 3단계 기능(픽셀 유동화)을 요청해서 만든다.
  - 편집 화면을 덮는 전체 화면 작업 모드다(CLAUDE.md 6장·기획서 '전체 화면 작업 모드'). 적용하면 실행 취소 한 단계, 취소하면 그대로다.
  - 고른 레이어 하나에 건다. 미리 보기는 그 레이어만 보인다(포토샵 유동화의 기본과 같다). 선택 영역과 상관없이 레이어에 건다.
  - 도구: 뒤틀기(손가락 방향으로 밂), 오목(가운데로 모음), 볼록(밀어냄), 재구성(원래대로 조금씩). 오목·볼록·재구성은 누르고 있으면 계속 걸린다(포토샵과 같다).
  - 크기(브러시 지름, 처음에는 문서 짧은 변의 15%)와 압력(1~100%, 기본 50%)을 고른다. 작업 모드 안에서 한 획씩 8번까지 되돌리고, 모두 되돌릴 수 있다.
  - 계산: 꼭짓점마다 '어디에서 가져올지'를 담은 변위 격자(꼭짓점 40만 개 이하, 칸 4~13px, 사이는 이어서 봄). 한 꼭짓점은 1000px까지만 옮긴다.
  - 미리 보기와 적용 모두 GPU 셰이더(AGSL)로 비튼다. 적용은 원본 해상도에서 1024px 묶음씩, 움직인 곳에 닿는 타일만 다시 그린다. 문서 밖을 읽는 곳은 가장자리 픽셀을 늘인다.
  - 다시 그린 타일 안에서 움직이지 않은 픽셀은 GPU 계산이라 값이 1/255쯤 달라질 수 있다. 이유: 브러시와 달리 한 번 적용하는 일이고, 움직이지 않은 타일은 그대로 둔다(최종 보고에서 알린다).
  - 도구 자리: 메인 도구 막대는 텍스트 다음, 커버 탭 줄은 텍스트와 레이어 사이다. 누르면 바로 작업 모드를 열고, 고른 도구로 남지 않는다. 아이콘은 Material Icons의 waves다.
  - 작업 모드 배치: 위 줄에 취소(X)·제목·한 획 되돌리기·모두 되돌리기·적용. 메인 가로는 오른쪽 칸(320dp), 커버·메인 세로는 아래 옵션(화면 높이의 40%까지)이다. 버튼·옵션은 힌지를 피하고, 캔버스는 편집 화면처럼 힌지를 지난다.
  - 취소(X·시스템 뒤로)는 묻지 않고 바로 닫는다. 이유: 포토샵 유동화의 취소와 같고, 잃는 것은 작업 모드 안의 획뿐이다(편집 화면의 문서는 그대로).
  - 도구·크기·압력은 앱을 끌 때까지 기억한다(브러시와 같다). 크기는 처음 열 때만 문서 짧은 변의 15%로 정한다.
- **리터칭(Claude 판단):** 사용자가 2단계 기능(복제 도장·스팟 복구)과 복구 브러시를 요청해서 만든다.
  - 도구 하나('리터칭', 반창고 아이콘)에 하위 도구 셋: 스팟 복구 브러시(처음)·복구 브러시·복제 도장. 길게 눌러 메뉴로, 또는 옵션 위쪽 줄로 바꾼다(CLAUDE.md 6장의 반창고 예와 같다).
    - 이유: 커버 탭 칸이 좁고, 라이트룸 모바일의 복구 도구처럼 한 도구에 모으면 찾기 쉽다. 포토샵은 복제 도장을 따로 둔다.
  - 고른 레이어 하나에 칠하고, 가져오는 픽셀도 그 레이어의 획 전 픽셀이다(포토샵의 '현재 레이어'). 선택 영역이 있으면 그 안에만 칠한다.
  - 복제 도장: 가져올 곳을 정하고 칠하면 그대로 베낀다(픽셀 값 그대로, 소프트웨어 그리기). 크기·단단함·불투명도.
  - 복구 브러시: 같은 곳에서 무늬를 가져오고, 손을 떼면 밝기·색을 둘레에 맞춘다. 결과 = 가져온 픽셀 + ('그 자리 - 가져온 픽셀'을 칠한 곳 바깥 둘레에서 안쪽으로 매끈하게 이은 값). 칠한 곳 안의 원래 픽셀(얼룩)은 쓰지 않는다.
    - 매끈하게 잇기는 구멍 메우기(pull-push)로, 칠한 곳과 둘레를 긴 변 512px 이하로 줄인 그림에서 Kotlin으로 하고, 더하기는 원본 해상도에서 GPU로 한다. 포토샵은 같은 생각을 더 정확한 방정식(푸아송)으로 푼다.
    - 이유: 원본 해상도에서 방정식을 풀거나 Kotlin으로 픽셀을 돌면 느리고 CLAUDE.md 2장에 어긋난다. 밝기·색 차이는 매끈해서 줄인 그림이면 충분하다. 아주 큰 획은 단단한 가장자리에서 가는 결이 조금 다를 수 있다(최종 보고에서 알린다).
  - 스팟 복구 브러시: 가져올 곳을 칠한 곳 둘레의 16방향 여러 거리에서 찾는다. 둘레 띠가 가장 비슷하고, 가져올 안쪽이 그 둘레와 비슷하며(다른 얼룩·경계를 피함), 가까운 곳이다. 칠한 곳과 겹치거나 문서 밖으로 나가는 곳은 뺀다. 찾지 못하면 그대로다.
    - 포토샵 스팟 복구의 '근접 일치'와 같은 생각이다. 포토샵 기본인 '내용 인식'은 큰 탐색(또는 AI)이라 3단계 '개체 제거'와 함께 본다.
    - 찾기는 긴 변 1024px 이하로 줄인 그림에서 Kotlin으로 한다(자동 선택과 같은 까닭, 최종 보고에서 알린다).
  - 가져올 곳: 옵션의 '가져올 곳 정하기'를 켜고(처음에는 저절로 켜짐) 캔버스를 누른 채 맞춘 뒤 떼면 정한다. 정한 뒤 첫 획이 간격을 정하고, 다음 획도 같은 간격으로 가져온다(포토샵의 '정렬' 기본값). 복구 브러시와 복제 도장이 같이 쓴다. 문서 크기가 바뀌면(자르기·회전·크기 변경) 지운다.
    - 이유: 포토샵은 Alt를 누르고 클릭하지만 터치 화면에는 Alt가 없다. 버튼으로 켜고 끄면 처음 쓰는 사람도 알 수 있다.
  - 표시: 가져올 곳은 브러시 크기의 원과 십자로 보인다(정하는 중에는 손가락 자리, 칠하는 동안에는 가져오는 자리를 따라감). 끄는 동안 복제·복구는 가져올 곳을 베껴 보이고(복구는 손을 떼면 맞춰진다), 스팟 복구는 칠한 곳을 반투명 검정으로 보인다(포토샵과 같다).
  - 설정(처음 크기 60px·단단함 50%·불투명도 100%)은 세 하위 도구가 함께 쓰고 앱을 끌 때까지 남는다. 복구 둘은 불투명도가 없다(포토샵과 같다).
  - 커버 탭 줄: 탭이 9개가 되어 칸이 56dp보다 좁아지면 그 폭으로 두고 옆으로 밀어 본다(누르는 영역이 48dp보다 좁아지지 않게). 고른 도구가 가려 있으면 보이게 민다. 메인 도구 막대도 낮은 화면(가로로 눕힌 폰)에서는 위아래로 밀어 본다.
    - 이유: 칸을 더 좁히면 이름이 잘리고 누르기 어렵다. 모바일 편집 앱의 도구 줄도 옆으로 민다.
  - 옵션 순서: 하위 도구 → 가져올 곳 정하기·안내 → 크기·단단함·불투명도. 이유: 메인 가로 오른쪽 칸은 옵션 자리가 좁아(45%), 처음 할 일(가져올 곳 정하기)이 아래에 있으면 가려졌다.
  - 경계 옆: 경계를 따라 칠하면 경계를 따라 옮긴 곳이 가장 잘 맞으므로 획 길이의 1.5배까지 찾고, 방향마다 가장 좋은 후보를 픽셀 단위로 다듬는다. 둘레 차이 중 크게 다른 곳(어긋난 경계)은 안쪽으로 번지지 않게 한다(그 자리 값은 그대로). 이유: 실제 앱에서 대각선 줄 옆을 칠했을 때 회색으로 번졌다.
  - 빠르기: 줄이지 않는 그림(작은 획)은 타일을 소프트웨어로 베끼고, 복구 합치기는 1024px 묶음마다 GPU를 한 번만 쓴다. 이유: GPU를 쓸 때마다 화면 그리기를 기다려, 소프트웨어 GPU인 에뮬레이터에서 획 하나가 25초 걸렸다.
- **명암 도구(Claude 판단):** 사용자가 명암 도구(번·닷지)를 요청해서 만든다(포토샵의 닷지·번).
  - 도구 하나('명암', Material Icons tonality)에 하위 도구 둘: 닷지(밝게, 처음, light_mode)·번(어둡게, dark_mode). 길게 눌러 메뉴로, 또는 옵션 위쪽 줄로 바꾼다. 스펀지(채도)는 요청에 없어 넣지 않는다.
  - 옵션: 범위(어두운 영역·중간 영역·밝은 영역), 노출(1~100%), 크기, 단단함. 처음값은 중간 영역·노출 50%(포토샵과 같다), 크기 100px·단단함 30%. 닷지·번이 함께 쓰고 앱을 끌 때까지 남는다.
  - 계산: 밝기 L(0.2126R + 0.7152G + 0.0722B)에서 범위의 무게(어두운 영역 (1-L)², 중간 영역 4L(1-L), 밝은 영역 L²) × 노출 × 0.5만큼, 닷지는 흰색 쪽으로, 번은 검은색 쪽으로 옮긴다. 채널마다 같은 비율이라 색이 크게 틀어지지 않는다.
    - 노출 100%여도 한 번에 반까지만 바뀌어, 여러 번 칠하면 쌓인다. 한 획 안에서 겹쳐 칠하면 한 번만 걸린다(브러시 불투명도와 같다). 부드러운 가장자리는 덜 걸린다.
    - 이유: 포토샵의 정확한 식은 공개되지 않았다. 범위마다 무게를 주고 획마다 쌓이는 방식이 같은 느낌을 낸다.
  - 고른 레이어에, 선택 영역이 있으면 그 안에만 건다. 투명한 곳(빈 타일)은 바꿀 색이 없어 그대로다.
  - 바꾼 색은 GPU(AGSL)로 계산하고 획 모양으로 얹기는 소프트웨어다(칠하지 않은 픽셀은 값이 그대로). 끄는 동안에는 레이어 축소본에서 바꾼 색을 보인다.
  - 도구 자리: 메인 도구 막대·커버 탭 줄 모두 리터칭 다음(막대 8개, 탭 10개).
- **HDR(Claude 판단, 유지하는 것은 사용자 결정):** HDR 사진의 밝기 정보(게인맵)를 지닌 채 편집하고, JPEG로 내보내면 원본처럼 HDR 사진(Ultra HDR)이 된다(안드로이드 14 이상).
  - 모델: 게인맵은 사진에서 온 레이어에 딸린 작은 그림이다(`Layer.gainmap`, 보통 원본의 가로·세로 1/4). 크기가 달라도 레이어 전체를 늘여 덮는다(안드로이드와 같다). 읽는 값(배율 최소·최대, 감마 등)은 문서에 하나다(`Document.hdr`). 이유: HDR 정보가 픽셀과 함께 다녀야 복제·병합·자르기 뒤에도 맞는 자리에 남는다.
  - 기하 편집: 돌리기·뒤집기는 게인맵도 같이 옮기고, 자르기는 같은 비율 자리를 가장 가까운 게인맵 칸 경계로 자른다(가장자리가 원본 약 2픽셀까지 어긋날 수 있지만 밝기 지도는 부드러워 보이지 않는다). 크기 변경은 늘여 덮으므로 고칠 것이 없다.
  - 내보내기: JPEG만 게인맵을 붙인다(안드로이드 압축기가 PNG·WebP에는 담지 못한다). 내보내기 창에 HDR이 남는지 한 줄로 알린다. 게인맵 크기는 사진의 비율대로 내보낼 크기에 맞춘다.
  - 겹치기 규칙: '밝히지 않음'(배율 1) 값으로 채운 뒤, 보이는 표준 레이어를 아래부터 그 레이어의 알파 × 불투명도만큼 그 레이어의 게인맵(없으면 '밝히지 않음')으로 덮는다. 그래서 사진 위에 칠한 그림·글자는 HDR로 밝아지지 않는다. 곱하기·스크린·오버레이 레이어는 아래 사진을 바꾸는 것이라 게인맵을 그대로 둔다.
  - 안드로이드 16의 ISO 게인맵: 방향이 'HDR→SDR'(HDR 사진을 밑에 둔 형식)이면 게인맵을 쓰지 않고 보통 사진으로 연다. 대체 색 영역은 sRGB·P3·BT.2020이면 지녔다가 다시 붙인다.
  - 저장: 게인맵 타일은 지금 타일 파일로, 크기·타일 목록은 레이어 덧붙임(꼬리표 2), 읽는 값은 문서 덧붙임(꼬리표 2)에 둔다. 실행 취소 기록의 메모리도 게인맵 타일을 센다.
  - 픽셀 편집: 게인맵이 있는 레이어를 고치면 게인맵도 같은 일을 한다(문서 좌표를 게인맵 배율로 줄여 같은 명령을 게인맵에 건다).
    - 유동화: 같은 변위로 비튼다. 리터칭 세 도구: 무늬를 가져온 자리의 게인맵을 같은 간격으로 베낀다(복구의 밝기 맞추기는 게인맵에 하지 않음). 브러시: 칠한 곳을 '밝히지 않음'으로 칠한다(같은 크기·단단함·불투명도). 지우개는 알파가 대신해 그대로 둔다.
    - 선택 영역이 있으면 게인맵 크기로 줄인 선택 영역 안에만 한다. 명암·보정은 게인맵을 그대로 둔다(밝기 차이는 그대로).
    - 선택을 새 레이어로 복사·잘라내기는 게인맵을 함께 쓴다(고르지 않은 곳은 알파가 0). 병합은 내보내기와 같은 겹치기로 게인맵도 합친다.
  - 편집 화면: HDR 문서를 여는 동안 창을 HDR 모드로 두고, 축소본·부분 그림에 화면용 게인맵을 붙여 HDR 화면이면 갤러리처럼 밝게 보인다.
    - 화면용 게인맵은 이미 그린 레이어 축소본으로 내보내기와 같은 겹치기를 해 만든다(크기는 축소본과 게인맵 중 작은 쪽). 레이어의 픽셀·게인맵·불투명도·혼합 모드가 그대로면 다시 만들지 않는다(보정 슬라이더를 끄는 동안 느려지지 않음). 부분 그림에는 그 자리만큼 잘라 붙인다.
    - 끄는 동안의 획은 기록한 뒤 게인맵에 들어간다. 유동화 작업 모드는 보통(SDR)으로 보인다. 이유: 작업 모드는 고른 레이어 하나만 보이는 미리 보기라, 비튼 게인맵을 따로 그리지 않는다.

## 설계 메모

해당 작업을 할 때 지킨다.

- **자동 저장:** `ProjectLibrary`(앱 전체에서 하나)가 저장·불러오기·지우기를 한 번에 하나씩 한다. 저장은 앱 전체 범위에서 돌아 편집 화면이 사라져도 끝까지 한다.
  - `EditorViewModel`은 사진을 열거나 새 캔버스를 만들면 새 프로젝트로 저장하고, 편집 뒤 1.5초 멈추면·닫을 때·onStop에 저장을 부탁한다.
  - 열린 프로젝트 번호는 `SavedStateHandle`(KEY_PROJECT)에 있다. 백그라운드 종료 뒤 되살리면 ViewModel이 그 프로젝트를 다시 연다.
  - 사진 주소(URI)가 아니라 타일 픽셀을 저장한다(사진 선택기 권한은 앱이 멈추면 사라진다). 값은 `copyPixelsToBuffer`·`copyPixelsFromBuffer`로 그대로 옮긴다.
  - 새 레이어 속성(보정 값 등)은 목차의 레이어 덧붙임(꼬리표)에, 새 레이어 종류(텍스트 등)는 내용 종류 코드에 더한다. 읽는 쪽이 모르는 덧붙임은 건너뛰고, 모르는 내용 종류는 판을 올린다.
- **저장 형식:** `BlendMode`는 순서(ordinal)나 이름이 아니라 고정된 코드 값으로 저장한다.
- **내보내기:** 엔진(`ImageExporter`)이 문서를 내보낼 크기의 비트맵 한 장으로 그리고(`render`) 압축한다(`RenderedImage.writeTo`). 앱(`ExportStorage`)이 갤러리 항목과 공유 파일을 만든다.
  - 그리기는 크기 변경의 묶음 그리기(`ImageResizer.renderBlock` → `PreviewRenderer.renderRegion`)를 쓴다. 혼합 모드를 축소본에 더하면 내보내기에도 같이 들어간다. 원본 크기 레이어 하나를 그대로 베끼는 길은 혼합 모드와 상관없다.
  - 사진 정보(EXIF)를 넣게 되면, 사진을 열 때 읽어 두고 자동 저장 형식에도 보관해야 한다.
  - 내보내기 창의 처음 고르기는 `EditorViewModel.exportChoice`다(이번 실행의 마지막 고르기, 없으면 설정의 기본값).
- **설정:** `AppSettings.get(context)`가 앱 전체에서 하나다. 새 설정은 `SettingsValues`에 기본값과 함께 더하고, 저장 키는 이름으로 두며, 모르는 값은 기본값으로 읽는다.
  - 테스트용 ViewModel 생성자(`EditorViewModel(application)`)는 저장하지 않는 `AppSettings.inMemory()`를 쓴다. 설정을 보는 테스트는 그것을 직접 넘긴다(`EditorSettingsTest`).
  - 설정 화면의 메인 2단 오른쪽은 `HingeAvoidingScrollColumn`이라, 항목 하나(이름 + 내용)가 한 덩어리로 띠를 피한다. 항목을 더할 때도 한 덩어리로 만든다.
- **편집 흐름:** 화면은 명령만 보낸다(`onEdit`). `EditorViewModel.edit`이 누르는 순간 바쁨(`Ready.busy`)을 켜고, 축소본 잠금 안에서 백그라운드로 계산한 뒤 메인 스레드에서 기록한다(`EditHistory.commit`).
  - 바쁜 동안 다른 편집·실행 취소는 무시한다. 두 손가락 보기는 된다.
  - 처리 중 막대는 바쁨이 0.2초 넘게 이어질 때만 보인다(`EditCanvas`). 보정을 놓을 때처럼 짧은 편집마다 깜빡이지 않게 한다.
  - `Ready.revision`은 보이는 문서가 바뀔 때마다 는다. 화면의 도구 상태(자르기 테두리 등)는 이것을 열쇠로 새로 시작한다.
- **도구 옵션:** 고른 도구는 `ToolSelection`(편집 화면 맨 위, `rememberSaveable`)이 든다. 하위 도구는 도구마다 따로 기억한다(`modeOf`).
- **색 고르기:** 색 줄은 `ColorRow`(`ColorControls`: 지금 색·최근 색·고르기·팔레트 열기), 팔레트는 `ColorPalettePrompt`(`PaletteDraft`, 편집 화면이 `rememberSaveable`로 들고 맨 끝에 띄움)다(`ColorPicker.kt`).
  - 고른 색은 `onChooseColor(대상, 색)` → `EditorViewModel.chooseColor`가 브러시·글자 색을 바꾸고 최근 색(`SettingsValues.recentColors`, `RecentColors.add`)에 더한다. 새 색 고르기(스포이드 등)도 이 길을 쓴다.
  - 스포이드: 화면은 `EyedropperActions`(시작·움직임·끝·그만둠)만 보내고, ViewModel이 `ColorSampler`로 읽어 `eyedropper`(자리·색)로 알린다. 읽는 중이면 끝난 뒤 그때의 마지막 자리를 이어 읽고(사이 자리는 건너뜀), 손을 뗀 뒤에 읽기가 끝나면 그 색을 쓴다.
  - 버튼을 켠 곳은 편집 화면이 든다(`eyedropperTarget`). 켜져 있으면 브러시·글자 손가락 대신 `EyedropperOverlay`를 겹친다. 꾹 누르기는 `PaintGestureOverlay`의 `hold`(`HoldActions`)로, 길게 누르기 시간 안에 움직이지 않으면 획을 버리고(`onCancel`) 손가락을 넘긴다.
- **선택 영역:** 원본은 `Document.selection`(엔진)이고, 화면은 윤곽선(`Ready.selection`, 확대하면 `Ready.selectionDetail`)만 받아 그린다(`SelectionAnts`).
  - 선택 영역만 바꾼 편집은 레이어 목록을 그대로 함께 쓴다. 그래서 ViewModel은 축소본과 부분 그림을 다시 그리지 않고 윤곽선만 다시 찾는다(`samePixels`).
  - 끄는 획은 시작할 때의 선택 영역을 들고 있어(`LiveStroke.selection`) 미리 보기도 그 안으로 자른다. 기록(`PaintStroke`)은 그때 문서의 선택 영역을 쓴다.
  - 새 도구가 선택 영역을 따라야 하면(리터칭·명암 등) 타일마다 `selection.tiles[key]`로 자르고(`BrushPainter.drawStroke`의 `clip`), 없는 자리는 건너뛴다. 옵션 자리는 커버는 캔버스와 탭 줄 사이, 메인 세로는 아래 패널(도구를 고르면 펼침), 메인 가로는 오른쪽 패널 맨 위다(그동안 조정 칸은 접어 둔다).
  - 도구 버튼의 길게 누르기는 `Modifier.longPressFirst`로 읽는다. M3 버튼·탭은 안쪽 클릭이 먼저 터치를 가져가기 때문이다.
  - 캔버스 위에 겹치는 도구 화면(자르기 테두리 등)은 `CanvasViewport`의 `overlay`에 넣는다. 두 손가락 감지를 가진 부모 안이라 확대·이동이 막히지 않는다.
  - 크기·단단함 슬라이더는 `SizeSlider`·`HardnessSlider`(BrushOptions.kt)를 쓴다. 미리 보기 상태(`SizePreviewState`)는 편집 화면과 유동화 작업 모드에 하나씩 있고, 컨트롤(`BrushControls` 등)의 `sizePreview`로 넘긴다.
- **레이어 패널:** 고른 레이어는 ViewModel이 든다(`activeLayer`). 실행 취소 등으로 없어지면 맨 위 레이어를 고른다(`activeLayerIn`).
  - 줄의 길게 누르기는 작은 그림·이름 쪽에만 `Modifier.longPressFirst`를 단다(줄의 고르기보다 먼저 알아챔). 메뉴는 `LayerMenu`, 병합 계산은 `LayerMerger`(MergeCommands.kt)다.
  - 화면은 `LayerControls`(목록·고른 레이어·끄는 불투명도)를 받아 그리고, 일은 `LayerActions`로 보낸다.
  - 순서를 옮기면 목록은 기록을 기다리지 않고 바로 새 순서로 보인다(`moveLayer`). 하지 못하면 `finishEditing`이 기록된 순서로 되돌린다.
  - 작은 그림은 `LayerPreviewCache.thumbnails`(래스터·보정 값이 같으면 다시 만들지 않음)가 만들고 `LayerSummary.thumbnail`로 넘긴다.
  - 합친 그림에 보이는지는 `Layer.isShown`(눈이 켜지고 불투명도 > 0)으로 거른다. 레이어를 그리거나 합치는 새 코드도 이것을 쓴다(스포이드 등). 화면용 게인맵 캐시의 열쇠에도 `visible`이 있다.
- **슬라이더:** 끄는 동안의 값은 ViewModel이 든다(`liveAdjustments`). 화면은 그 값을, 없으면 기록된 값을 보인다.
  - 미리 보기(`previewAdjustments`)는 바꾸는 함수를 받아 ViewModel의 지금 값에 건다. 화면이 한 박자 늦은 값을 들고 있어도 다른 항목을 덮어쓰지 않는다.
  - 놓으면(`commitLive`) 편집 흐름으로 한 번 기록하고, 기록·실패와 함께 끄는 값을 지운다. 버튼(초기화)은 `recordAdjustments`로 바로 기록한다.
  - 처리 중에 온 미리 보기·기록은 `runPendingLive`가 편집이 끝난 뒤 이어서 한다. 놓은 값이 기록된 값과 같은데 미리 보기를 보이고 있었으면 기록된 문서로 다시 그린다.
  - 불투명도도 같은 흐름이다(`previewOpacity`·`liveOpacity`). 놓으면 `commitLive`가 끄던 값을 한 번에 기록한다(둘이면 `EditSequence`로 한 단계).
- **실행 취소 기록 메모리:** `EditHistory`는 단계 수(50)와 메모리 한도(`maxBytes`, 기기 메모리의 1/8)를 함께 지킨다. 타일은 객체 기준으로 한 번씩 센다.
  - 무거운 편집은 늘어날 메모리를 어림해(`CancellableCommand.estimateNewBytes`) 모자라면 오래된 단계부터 버리고(`EditorViewModel.makeRoom`), 그래도 모자라면 알리고 하지 않는다. 브러시도 이 흐름을 쓴다.
- **브러시:** 자국 자리는 `StrokeDabs`(순수 Kotlin, 지름의 10% 간격)가 정하고, 그리기는 `BrushPainter`(기록·미리 보기 공통)가 한다.
  - 기록은 `PaintStroke`(획이 닿는 타일만 소프트웨어로 새로 그림)다. 지우개는 빈 타일을 건드리지 않는다.
  - ViewModel은 끄는 획(`drawing`)과 기록을 기다리는 획(`queuedStrokes`)을 미리 보기에 얹는다(`LiveStroke`). 기록하는 순간(`runEdit`의 `onCommitted`) 기다리는 목록에서 빼서 두 번 그려지지 않게 한다.
  - 확대 그림에 획을 얹는 쉬운 경우는 `strokesFitDetail`이 고른다(맨 위 표준 레이어, 지우개는 레이어가 하나일 때).
  - 획을 기록한 뒤 축소본은 바뀐 타일 자리만 다시 그린다(`LayerPreviewCache.patch`, 전체를 그린 것과 픽셀이 같다).
- **타일 메모리:** 레이어가 많아지면 쓰지 않는 타일을 앱 저장 공간으로 내보내 메모리를 아낀다. 레이어·브러시 작업 때 만든다.
- **큰 사진 조각 해독:** 사진을 띠 모양 조각으로 해독하면(`BitmapRegionDecoder`) 해독기 한도를 피하고, 여는 순간 메모리(지금 해독본의 2.5배)도 줄어 200MP 원본을 열 수 있다. EXIF 방향은 직접 돌려야 한다.
- **축소본:** `PreviewRenderer`가 화면 크기에 맞는 1/2^k 단계로 GPU에서 그린다. 레이어는 보정을 걸어 그리고 불투명도·혼합 모드로 얹는다(표준·불투명도 1이 아니면 `saveLayer`로 따로 그려 `layerPaint`로 얹음).
  - 계산 기준은 `BlendMath`(순수 Kotlin)이고, 안드로이드 혼합 모드는 `BlendMode.MULTIPLY` 등이다(`PorterDuff.Mode.MULTIPLY`는 다른 계산). 새 혼합 모드는 `LayerBlend.kt`의 대응과 `BlendMath`, 저장 코드(`ProjectManifestCodec.blendCode`)에 함께 더한다.
  - 확대해서 보면 ViewModel이 보기가 0.15초 멈춘 뒤 보이는 곳(1/8 여유)을 알맞은 단계로 다시 그린다(`renderRegion`, `Ready.detail`). 그리는 일(전체·부분)은 잠금으로 한 번에 하나만 한다.
  - 편집·실행 취소로 문서가 바뀌면 전체 축소본을 다시 그리고, 부분 그림은 버린 뒤 다시 그린다(`EditorViewModel.showPreview`).
  - 레이어의 픽셀이 조금만 바뀌었으면(타일의 절반 이하) 그 레이어 축소본은 바뀐 타일 자리만 다시 그린다(`LayerPreviewCache.patch`). 실행 취소도 같다.
- **캐시:** 썸네일·GPU 텍스처는 `LayerId`가 아니라 `Raster`·`Tile` 객체를 기준으로 한다. 실행 취소 뒤 레이어 번호가 다시 쓰이기 때문이다.
- **넓은 색:** 엔진의 비트맵은 모두 sRGB 꼬리표이고 값만 문서 색 공간(`Document.colorSpace`)의 값이다(`DocumentColors`).
  - 새 비트맵을 만들 때 색 공간을 주지 않는다(sRGB). 화면에 그릴 때만 `DocumentColors.forScreen`, 압축하기 전에만 `tagForEncoding`으로 꼬리표를 바꾼다. 엔진이 다시 쓰는 그림의 꼬리표는 바꾸지 않는다.
  - 새 명령이 sRGB로 고른 색을 칠하면 `DocumentColors.paintColor`를 거친다. 임시 문서(`Document.create`)는 sRGB라 색을 칠하지 않는 계산에만 쓴다.
- **HDR 게인맵:** 레이어마다 `Layer.gainmap`(늘여 덮는 작은 래스터), 읽는 값은 `Document.hdr`. 안드로이드 게인맵과 오가는 일은 `Gainmaps`(14 전용 부분은 `Gainmaps.supported`로 막음), 겹치기는 `GainmapComposer`다.
  - 레이어를 새로 만드는 명령은 게인맵을 어떻게 할지 정한다(복제·선택 복사는 함께 씀, 새 레이어·글자는 없음). 레이어 픽셀을 옮기거나 다시 그리는 새 명령은 게인맵도 같이 고친다(`GainmapEdits`: 브러시·리터칭·병합, 유동화는 `LiquifyRenderer.warpGainmap`).
  - 저장 형식의 덧붙임 꼬리표: 레이어 1 보정·2 게인맵, 문서 1 색 공간·2 HDR 값.
  - 편집 화면: ViewModel이 `LayerPreviewCache.screenGainmap`을 `Ready.gainmap`(`ScreenGainmap`, 안드로이드 클래스를 앱에 드러내지 않음)으로 넘기고, 화면은 그릴 때 `DocumentColors.forScreen(…, gainmap, 보이는 문서 자리, 문서 크기)`로 붙인다. 창 모드는 `EditScreen`의 `WindowColorMode`다.
- **전체 화면:** `MainActivity`가 처음과 창이 다시 앞에 올 때(`onWindowFocusChanged`) `hideStatusBar(window)`를 부른다(`ui/layout/SystemBars.kt`).
  - 아래 시트(`ModalBottomSheet`)는 화면 전체를 덮는 따로 창이라, 시트가 앞에 오면 상태 표시줄이 다시 나온다. 시트 내용 맨 앞에 `HideStatusBarInSheet()`를 둔다(새 시트도). 메뉴(팝업)·`HingeAwareDialog`(앱 창 안)는 그대로 숨어 있다(`SystemBarsTest`).
  - 상단 바는 `rememberTopBarInsets(바 높이)`, 버튼·제목마다 `Modifier.topBarItem(…, 이름)`, `windowInsets = barInsets.windowInsets()`를 쓴다(`TopBarInsets.kt`). 새 상단 바나 바 안의 버튼을 더할 때도 단다. 편집·유동화 바 높이는 `WorkTopBarHeight`(48dp)다.
- **힌지 피하기:** 패널 내용(레이어 목록·슬라이더)이나 버튼을 새로 넣을 때도 힌지를 피한다.
  - 창(대화상자)은 `AlertDialog`·`Dialog` 대신 `HingeAwareDialog`를 쓴다. 화면 전체를 덮는 자리(Box의 마지막 자식)에 둔다.
  - 세로로 쌓으면 `HingeAvoidingColumn`, 두 개를 나란히 두면 `HingeSplitRow`, 구석에 하나를 두면 `HingeAvoidingTopStart`(`ui/layout/HingeAwareLayouts.kt`)를 쓰거나 같은 방식으로 만든다.
  - Compact(커버) 배치는 힌지를 보지 않는다.
  - 메인 세로에서는 창이 접히는 선 위쪽 절반(Pixel_Fold 에뮬레이터 약 380dp)에 들어간다. 창 내용은 짧게 하고, 칸에 대한 안내는 칸 바로 위에 둔다. 키보드가 열리면 창이 낮아지고 고치는 칸이 보이게 스크롤되기 때문이다(크기 변경 창).
  - 폴드8 실기기(2026-10-17 사용자 기기에서 확인): 펼친 기본 방향은 2448×1848 창의 가운데(x=1224)를 지나는 세로선(메인 가로, Expanded), 돌리면 1848×2448 창의 가운데(y=1224)를 지나는 가로선(메인 세로, Medium)이다. 두께 0(FLAT)이고 Pixel_Fold 에뮬레이터와 방향이 같다. 접으면 없다.
- **타일 공유:** 한 가지 색 새 캔버스는 타일 한 장을 모든 자리(최대 약 800자리)가 함께 쓴다(`Raster.filled`).
  - 메모리 한도·타일 내보내기·저장 형식은 타일을 자리가 아니라 객체 기준으로 센다.
  - 끝 자리 타일의 캔버스 밖 부분은 읽지 않는다. 캔버스를 키우는 작업은 그 부분을 비우고 쓴다.
- **캔버스 표시:** `CanvasImage`가 보기 상태(`CanvasView`: 맞춤·자유)의 변환대로 체크 무늬 → 전체 축소본 → 부분 그림 → 테두리를 그린다. 보이는 픽셀만 그린다.
  - 보기 상태는 화면 쪽(`CanvasViewState`, `rememberSaveable`)이 들고, 엔진 쪽에는 `Viewport`(배율·보이는 문서 영역)만 알린다.
  - 화면 회전(다음 후보)은 `CanvasView.Free`에 각도를 더하고, `ViewTransform`과 보이는 영역 계산이 회전을 다루게 바꾸는 일이다.
- **한 손가락 도구:** 두 손가락 조작은 도구보다 먼저(Initial 단계) 읽고, 시작되면 손가락을 모두 뗄 때까지 터치를 소비한다(`CanvasGestures.kt`). 브러시 같은 도구는 소비된 터치를 보면 하던 동작을 멈춘다.
  - 두 손가락 톡(설정)이 켜져 있으면, 두 손가락이 닿고 움직이지 않은 터치의 손을 떼는 순간을 소비한다. 한 손가락 톡을 쓰는 도구는 소비된 손 떼기를 보면 취소해야 한다(`detectTapGestures`는 그렇게 한다).
- **홈 최근 프로젝트:** `RecentProjectsGrid`(`LazyVerticalGrid`)는 위쪽 고정 영역 아래에서만 스크롤한다. 세로 스크롤 `Column` 안에 넣으면 높이가 무한대라 오류가 난다.
  - 세로 힌지: 칸마다 실제 창 위치를 재서(`onGloballyPositioned`) 띠에 걸리는 쪽 안쪽 여백을 준다(`insetsAvoiding`). 칸 너비로 어림하면 격자의 픽셀 나눔과 몇 픽셀 어긋난다.
  - 가로 힌지: 스크롤하는 카드는 지나갈 수 있다(결정 기록 '홈 최근 프로젝트'). 위쪽 버튼·제목은 피한다.

## 기술 주의점

- material3 1.4.0의 `TopAppBar`는 `@OptIn(ExperimentalMaterial3Api::class)`가 필요하다. 매개변수 타입 `TopAppBarScrollBehavior`가 실험 기능이기 때문이다.
- 아이콘은 Android Studio 'Vector Asset'의 Material Icons 파일을 쓰고, `android:tint="?attr/colorControlNormal"` 줄은 뺀다. 이 프로젝트에는 AppCompat이 없어서 그 줄이 있으면 빌드가 실패한다.
- `List.removeFirst()`·`removeLast()`는 안드로이드 13·14 기기에서 오류가 나므로 `removeAt(0)` 등을 쓴다.
- 색 공간:
  - `ColorSpace.isWideGamut`은 값의 범위만 넓은 extended sRGB(16비트 PNG를 풀면 나옴)도 참이다. 넓은 색은 원색 넓이로 판단한다(`DocumentColors.isWiderThanSrgb`).
  - `Bitmap.setColorSpace`는 값을 바꾸지 않고 꼬리표만 바꾼다. 하드웨어 비트맵은 꼬리표를 바꾸는 대신 `Bitmap.wrapHardwareBuffer(bitmap.hardwareBuffer, 색 공간)`으로 같은 메모리를 감싼다(복사 없음).
  - `Bitmap.setPixel(s)`·`getPixel`은 sRGB 값으로 보고 비트맵 색 공간과 바꾼다. 값을 그대로 다루려면 sRGB 꼬리표에서 다룬 뒤 꼬리표만 바꾼다(테스트).
- 게인맵(`android.graphics.Gainmap`):
  - 기본 API는 34, `getGainmapDirection`·`getAlternativeImagePrimaries`는 36이다(SDK `api-versions.xml`). 엔진 모듈에는 androidx가 없어 `@RequiresApi` 대신 SDK의 `@TargetApi`를 쓴다.
  - 게인맵 그림에는 색 공간이 없고 1채널은 ALPHA_8이다. ALPHA_8을 그리면 붓 색 × 알파인 마스크로 그려져, 검은 바탕에 흰 붓으로 얹으면 회색 = 값이다.
  - `Bitmap.compress`는 JPEG에만 게인맵을 담는다(ALPHA_8은 1채널로 씀). `Bitmap.copy`는 게인맵도 함께 복사한다.
- Kotlin의 `apply { }` 안에서는 수신 객체(예: Canvas)의 `width`·`height`가 바깥 클래스의 같은 이름보다 먼저 쓰인다(테스트에서 겪음). 바깥 값은 미리 지역 변수로 받아 쓴다.
- Gradle 9.6은 JDK 25로 실행한다. PC의 기본 java가 오래되었으면, 명령마다 `JAVA_HOME`을 Android Studio 내장 JDK(`jbr` 폴더)로 지정한다.
- API 37부터 `ImageDecoder`는 사진 하나를 푸는 데 약 0.5GiB(536,900,000바이트)까지만 쓴다.
  - EXIF로 돌려 보여 주는 사진은 같은 크기의 임시 버퍼를 하나 더 쓰고, 그것도 한도에 들어간다.
  - 한도를 바꾸는 `setAllocationLimit`은 SDK 소스에는 있지만 공개 SDK(android.jar)에는 없어 앱이 쓸 수 없다.
  - 그래서 8비트 사진은 약 134MP(회전이면 약 67MP)보다 크면 원본 크기로 못 연다(`ImportSizing.decodeBytes`, `PhotoImporter.decodeLimitBytes`).
- `Bitmap.createBitmap(원본, x, y, w, h)`는 바꿀 수 있는 비트맵을 돌려준다. 비트맵을 바꿀 수 없게 하는 공개 함수가 없으므로, 바꿀 수 없는 복사본은 `copy(ARGB_8888, false)`로 만든다(메모리가 없으면 null).
- `Bitmap.createBitmap(Picture, …, HARDWARE)`는 null이 아니라고 적혀 있지만, GPU가 실패하면 null을 돌려줄 수 있다.
- `connectedDebugAndroidTest`는 앱 설치에 실패해도 `BUILD SUCCESSFUL`로 끝날 수 있다. 결과 XML의 테스트 수로 확인한다(`docs/emulator.md`).
- 비트맵을 반 크기로 그릴 때 홀수 크기면 끝 픽셀이 반만 덮여 투명하게 빠진다. `PreviewRenderer.drawScaled`처럼 셰이더(CLAMP)로 올림한 크기를 채운다.
- material3 1.4.0의 `ModalBottomSheet`도 `@OptIn(ExperimentalMaterial3Api::class)`가 필요하다. 내용이 화면 반보다 길면 반만 펼쳐지므로 `skipPartiallyExpanded = true`로 연다.
- M3 `Surface`는 자기 아래 형제에게 가는 터치는 막지만, 부모의 터치 처리는 막지 않는다. 바깥을 눌러 닫는 바탕은 카드의 부모가 아니라 형제로 깐다(`HingeAwareDialog`).
- Compose 화면 테스트는 Espresso 3.7.0 이상이 필요하다. 3.5.1은 API 37에서 없어진 `InputManager.getInstance`를 불러, 화면 테스트가 모두 바로 실패한다.
- 화면 테스트의 화면 크기는 `DeviceConfigurationOverride.ForcedSize`로 정한다. 정한 크기가 기기 화면보다 크면 밀도를 낮춰 맞추므로, 테스트에서 dp를 픽셀로 바꿀 때는 노드의 밀도(`layoutInfo.density`)를 쓴다.
  - 화면 루트(`onRoot`)는 강제 크기 바깥이라 기기 밀도 그대로다. 강제 크기 안쪽 노드의 밀도를 쓴다.
- `Paint()`·`Paint(0)`에도 비트맵 필터가 켜져 있다(SDK의 HIDDEN_DEFAULT_PAINT_FLAGS). 픽셀을 그대로 옮기려면 필터·안티에일리어싱을 끄고 SRC로 그린다(`CanvasTileComposer`).
- Picture에 기록한 뒤 `Bitmap.createBitmap(picture, w, h, ARGB_8888)`으로 그리면 소프트웨어로 그려지고, 바꿀 수 없는 비트맵이 나온다.
- 화면 테스트에서 누르거나 글자를 넣은 직후에는 화면이 아직 다시 그려지지 않았을 수 있다. 화면을 찍기 전에 `waitForIdle`을 부른다.
- 화면 테스트의 `performClick`은 노드의 보이는 부분을 누른다. 키보드가 열려 창 내용이 스크롤되는 등으로 노드가 다 가려지면 엉뚱한 곳(창 왼쪽 위)이 눌렸다. 그때는 `performSemanticsAction(SemanticsActions.OnClick)`을 쓴다.
- `Bitmap.compress`:
  - JPEG는 알파를 미리 곱한 값을 그대로 써서 투명한 곳이 검게, 반투명한 가장자리가 어둡게 된다. 그래서 JPEG는 흰 바탕 위에 합성한다(`ImageExporter`).
  - 압축기는 비트맵 말고도 메모리를 더 쓴다(JPEG 픽셀당 약 3B, WebP 약 6.5B). 한 변 한도는 WebP 16383px, JPEG 65500px이다.
  - 쓰다가 난 예외는 지우고 실패(false)만 알린다. 그래서 취소였는지 따로 확인한다.
- 하드웨어 비트맵은 소프트웨어 캔버스에 그릴 수 없다(예외). GPU로 그린 것은 `copy(ARGB_8888, false)`로 읽어 온 뒤 쓴다.
- 갤러리(MediaStore)에 넣을 때는 다 쓸 때까지 IS_PENDING=1로 둔다. 쓰는 중인 항목은 약 7일 뒤 저절로 지워진다. 권한은 필요 없다.
- FileProvider는 매니페스트에 그대로 쓰지 말고 작은 하위 클래스로 쓴다(`ShareFileProvider`). 공유 창은 앱이 화면에 있을 때(STARTED) 띄운다.
- 폰을 무선 디버깅으로 연결해 두면 기기가 둘이 되어, adb 명령은 기기를 골라야 한다(`adb -s emulator-5554 …`). `connectedDebugAndroidTest`도 연결된 모든 기기에서 돈다.
  - 에뮬레이터에서만 돌리려면 `ANDROID_SERIAL=emulator-5554`를 붙인다. AGP가 이 환경 변수로 기기를 고른다(라이브러리 안에서 확인, 아직 실제로 써 보지는 않았다).
  - 확실한 방법은 gradle로 APK만 만들고 `adb -s emulator-5554`로 설치·실행하는 것이다(`docs/emulator.md` '에뮬레이터 테스트', 2026-10-18에 씀).
- `EditorViewModel`은 `(Application, SavedStateHandle)` 생성자를 쓴다. 안드로이드의 기본 ViewModel 공장이 이 생성자를 고른다. 테스트용으로 `(Application)` 생성자를 따로 둔다.
  - 테스트가 직접 만든 ViewModel은 화면이 갖지 않아 테스트가 끝나도 정리되지 않는다. 편집 뒤 잡아 둔 자동 저장(1.5초 뒤)이 테스트가 폴더를 지운 다음에 돌아 프로젝트를 다시 만든다(에뮬레이터 홈에 테스트 캔버스가 남았다).
  - 그래서 실제 ViewModel로 문서를 여는 테스트는 `@After`에서 `deleteTestProjects(context, viewModel)`를 부른다(`TestProjects.kt`: 닫고, 저장이 끝나기를 기다린 뒤 지움).
- Pixel_Fold 에뮬레이터는 화면이 둘이라 `adb exec-out screencap -p`에 `-d <화면 번호>`를 준다(`adb shell dumpsys SurfaceFlinger --display-id`).
- 화면 테스트에서 화면 읽기 동작을 이름으로 부르는 `performCustomAccessibilityActionWithLabel`은 실험 기능(`ExperimentalTestApi`)이다.
- 화면 테스트에서 노드의 `layoutInfo.coordinates`는 모든 Modifier 안쪽, 곧 눈에 보이는 부분이다. Material 버튼의 48dp 최소 터치 영역은 그 바깥이므로, 힌지 검사는 `touchBoundsInWindow`로 48dp까지 넓혀 본다(`HingeAssertions.kt`).
- 안드로이드는 앞에 온 창이 화면 전체를 덮으면(MATCH_PARENT, 아래 시트 등) 상태 표시줄을 그 창의 설정대로 보이고, 덮지 않는 창(팝업 메뉴)이면 아래 앱 창의 설정을 그대로 둔다. 그래서 상태 표시줄을 숨긴 앱에서 시트를 열면 시트 창에서도 숨겨야 한다.
- 안드로이드 15 이상에서 targetSdk 35 이상이면 창이 카메라 구멍 자리까지 그린다. 상태 표시줄을 숨기면 위쪽 내용이 구멍과 겹칠 수 있다. 구멍 자리(`rootWindowInsets.displayCutout.boundingRects`)는 창 좌표다.
- Pixel_Fold 에뮬레이터의 바깥(커버) 화면에는 위 가운데에 카메라 구멍이 있고(1080px 폭에서 480~590px, 높이 110px), 안쪽 화면에는 없다. 안쪽 화면에 구멍을 흉내 내려면 개발자 옵션 '디스플레이 컷아웃'과 같은 `adb shell cmd overlay enable com.android.internal.display.cutout.emulation.corner`(오른쪽 위 구석) 등을 켜고, 끝나면 `disable`로 되돌린다(바깥 화면에는 걸리지 않았다).

## 확인 방법

- 빌드·테스트: `./gradlew assembleDebug test`
- 화면은 에뮬레이터에서 아래를 확인한다. 에뮬레이터 만들기와 명령·요령은 `docs/emulator.md`에 있다.
  - 홈 → 편집 → 뒤로
  - 접기·펼치기(Pixel_Fold): 커버(Compact)·안쪽 기본 방향(Expanded)·안쪽 돌린 방향(Medium), 힌지 정보는 `adb logcat -s WindowHinges`
  - 창·시트: 펼친 화면에서 힌지 한쪽에 뜨는지, 키보드를 열어도 버튼과 안내가 보이는지, 메인 세로에서 스크롤하지 않아도 다 보이는지
  - 편집: 회전·뒤집기·자르기·크기 변경 뒤 실행 취소·다시 실행, 큰 사진의 처리 중 표시
  - 내보내기: 갤러리 '사진/Stratum'에 생긴 파일의 크기·형식(adb pull로 꺼내 확인한 뒤 지운다), 공유 창
  - 가로 화면
  - 전체 화면: 홈·편집·설정·시트에서 상태 표시줄이 숨는지, 위에서 밀면 잠깐 보이는지
  - 한국어 문구
  - 캔버스 확대·이동: 두 손가락 조작은 adb로 흉내 내기 어려워 화면 테스트(`CanvasViewportTest`·`CanvasSharpenTest`)로 본다. 부분 그림은 `adb logcat -s EditorViewModel`의 "Detail level" 줄로 본다.
